# 高宇 NL2DSL 深度模拟面试训练

## 使用方法

这份材料配合[简历](高宇-AI%20Agent-NL2DSL-大数据语义层-8年.md)、[追问清单](高宇-NL2DSL简历面试官追问清单.md)和[参考答案](高宇-NL2DSL简历面试参考答案.md)使用。参考答案用于查漏，不用于逐字背诵。每次练习只选一条追问链，先录音回答，再回看代码或证据，最后重答一次。

每题按四步说：**结论（20秒）→ 亲手做的实现（1分钟）→ 一个失败或取舍（1分钟）→ 证据与边界（30秒）**。被追问时只展开面试官问的那一层。

## 先做真实性盘点

面试前自己填写。没有亲手做过、没有证据的内容不要用“我负责”“已经上线”“提升了90%”表达。

| 简历表述 | 我的真实职责/接触范围 | 可展示的证据 | 目前缺口 |
| --- | --- | --- | --- |
| 公司智能数据查询平台 | 待填写：具体模块、时间、交付物、上线范围 | 待填写：脱敏设计/接口/测试/复盘 | 待填写 |
| 个人开源 NL2DSL | 待填写：亲自设计、实现和 AI 辅助生成各占什么 | GitHub 代码、提交、测试 | 待填写 |
| 数据资产与语义层元数据加工 | 待填写：真实输入表、输出表、调度、任务优化 | 脱敏表结构/SQL/任务日志 | 待填写 |
| Rerank 800ms→80ms、成本降90%、准确率约90% | 待填写：样本量、候选数、机器、计时范围、统计口径 | 基准报告/脚本/原始结果 | 待填写 |
| Qdrant、Spark、Yarn、HDFS 等技能 | 待填写：在哪个项目实际使用、自己做了什么 | 代码/任务/故障实例 | 待填写 |

**当前核查提醒**：开源仓库能看到 Graph、DSL、RAG、权限和评测代码，但这不能证明公司项目的职责。当前检索到的 `reports` 未直接证明简历中的 800ms→80ms、成本降90% 及“整体准确率约90%”三组数字。若拿不出同一口径的实验记录，应在面试前调整简历表述，或明确说这是个人实验且说明实验条件。

## 模拟面试规则

- 一轮 35 分钟：3分钟自我介绍，20分钟连续追问，7分钟现场代码/白板，5分钟复盘。
- 回答不能引用“文档里这么写”。要说输入、输出、依赖、错误处理、验证方式，并指出自己负责的部分。
- 面试官连续追问到第三层；答不出就明确“我没有做过/没有数据”，随后说自己做过的相邻部分和验证方法。
- 每道主问题满分 10 分：真实性与边界 2、实现细节 3、取舍和失败路径 2、证据 2、表达 1。任何捏造数据或把开源实现说成公司上线能力，该题计 0 分。
- 通过线：每条链至少 7 分，项目边界、DSL 安全、Spark 真实性三条链不能低于 8 分；现场能独立讲清至少一个实际代码路径。

## 第一轮：项目到底是谁做的

**主问题**：你简历写“负责 NL2DSL 核心架构设计与实现”。公司项目和 GitHub 开源仓库是什么关系？你本人到底做了什么？

1. 公司侧你亲自交付的一个模块是什么？说清需求方、输入、输出、上下游。
2. 这个模块在哪个时间段完成？当时有几个人参与？你独立决定过什么？
3. 举一个当时踩的坑。最初方案、失败现象、最后修改是什么？
4. 开源仓库里对应的文件是哪几个？哪些是个人复现，哪些只是架构思路相似？
5. 面试现场我打开仓库，随机点一个函数，你能解释调用方、返回值和异常路径吗？
6. 如果公司代码不能展示，请用脱敏结构图、接口契约或测试用例证明你的参与范围。

**合格特征**：始终能把公司实践、个人开源和设想中的生产方案分开；至少有一个完整的亲手交付案例。**红灯**：只重复“架构设计、核心开发、企业级”，讲不出模块边界。

## 第二轮：白板画出真实查询链路

**主问题**：用户问“华东近7天销售额最高的5个商品”，从 API 到返回结果，画出数据流。

1. 请求里除了问题还需要哪些身份和业务域信息？这些信息能否由 LLM 决定？
2. 召回了什么治理资产？哪一个是权威口径，哪一个只是给模型提示？
3. 写出你项目 DSL 的关键字段和值；说清“近7天”的边界、时区及“销售额”的口径来自哪里。
4. DSL 结构合法但指标未注册，在哪一步失败？修正为什么不会无限循环？
5. 用户只能看华东区域，权限条件如何和用户条件合并？OR 条件会不会绕过？
6. SQL 构建后，扫描、沙箱、执行分别拦什么？执行失败能不能一律让模型重写？
7. 最后返回哪些数据和解释？审计里记录什么？

**代码核对点**：`D:\demo\db-gpt\NL2DSL\nl2dsl\graph\builder.py` 的顶层路径是 `clarification → plan → decompose → validation 子图 → permission_check 子图 → resolve_semantic → optimize_dsl（启用时）→ confidence → build_sql → scan_sql → sandbox_check → execute_sql → verify_dsl → explain`，其中有条件分支。`generate_dsl`、`validate_dsl`、`correct_dsl` 在 validation 子图中；不要把概念清单当成一条无分支的实际执行路径。现场再对照 `subgraphs.py` 和 `nodes.py` 讲当前版本。

**白板验收**：用箭头画出正常路径、校验失败分支、权限拒绝分支各一条；说明哪些环节可重试，哪些必须终止。

## 第三轮：DSL、权限和安全

**主问题**：你说 DSL 比直接生成 SQL 更安全。假设我就是攻击者，为什么我不能用提示词让系统查出所有手机号？

1. 请说出 DSL Schema 的具体约束，区分 Pydantic 结构校验和注册表语义校验。
2. 如果模型选择了合法字段，但该用户无权访问，在什么位置拦截？
3. 行级权限注入时，如何确保不能被用户原有的过滤条件覆盖？
4. 列级权限是拒绝、移除还是脱敏？这三种策略分别有什么风险？说当前项目实际做法。
5. SQL 扫描能发现合法 SQL 查错指标口径吗？不能的话靠什么发现？
6. 数据库连接账号需要什么权限？即使上游校验有 bug，还有什么防线？

**现场题**：在纸上给出一个越权 DSL 和预期处理结果，再指出仓库里负责这项检查的代码位置。不要把“理论上应当”说成“当前代码已实现”。

## 第四轮：RAG 与性能数字

**主问题**：你简历说 Rerank 从约 800ms 到约 80ms、成本降约 90%、准确率约 90%。请拿实验设计解释。

1. 原方案和新方案分别是什么？计时从哪行开始、哪行结束？含网络、冷启动和缓存吗？
2. 评测样本有多少？每题召回多少候选？机器配置、模型版本、并发度一样吗？
3. 800ms 和 80ms 是均值、中位数还是 P95？方差和失败请求怎么处理？
4. 成本的分母是什么？是 token 调用费、推理资源，还是整套系统成本？
5. 准确率的分母、标注标准和基线是什么？“整体准确率”是否能被单一数字概括？
6. Rerank 结果错了，后续 DSL 校验能发现所有语义错误吗？

**合格特征**：能展示脚本和结果，或坦诚说目前缺原始记录并撤回精确数字。代码核对从 `nl2dsl/rag/retriever.py`、`reranker.py` 和 `reports` 开始。开源项目没有 Elasticsearch；技术选型不能讲成项目里已经用了 ES。

## 第五轮：Spark 元数据加工真实性

**主问题**：你说用 Spark SQL 加工表、字段、指标、术语、权限，给我画一张真实的输入到输出表图。

1. 输入来自数据库系统表、业务配置表、字典表还是日志？举出真实存在的字段，敏感名称可脱敏。
2. 一条指标元数据如何和来源表、字段、统计口径、版本关联？更新策略是什么？
3. 为什么这件事要用 Spark？数据量、复杂度、上游格式或调度约束是什么？如果 MySQL SQL 足够，为什么还选 Spark？
4. 一次慢任务是哪个 stage 慢？Spark UI 的 shuffle read、task 耗时和 skew 指标是什么样？
5. 你改了什么 SQL/分区/Join 策略？优化前后用什么指标验证？
6. 源字段改名、指标口径变更后，向量索引与语义配置如何同步？如何回滚？

**合格特征**：至少能讲一个真实任务的输入表、输出表、分区键、调度频率、失败重跑和下游消费。无法讲清的项目表述应缩小到真实参与范围。

## 第六轮：Vibe Coding 现场验证

**主问题**：这个开源项目借助 AI 写了多少？你不用 AI 能修改吗？

1. 选一个你最熟的模块，解释为什么这样设计接口和状态。
2. 指出一次 AI 给出的错误方案；你如何发现、改动、写测试？需要真实提交或测试佐证。
3. 现场需求：给 DSL 的某个过滤操作符补一条类型校验。你会先读哪些文件？
4. 哪些验证属于单测，哪些要跑集成或端到端？
5. 如果 AI 重构后测试通过但权限语义变了，怎么发现？

**合格特征**：可以独立读懂代码、讲出取舍、做小改动；承认 AI 参与而不把每个提交都说成亲手逐行编写。

## 第七轮：Java 后端稳定性

**主问题**：日抓拍千万级，RabbitMQ 消息积压，告警推送延迟升高。你接手后前 30 分钟怎么排查？

1. 看哪些图或命令，如何判断生产变快还是消费变慢？
2. 消费者在哪一步 ack？数据库写入成功但 ack 前进程崩溃怎么办？
3. 业务幂等键是什么？唯一索引和状态更新怎么设计？
4. 算法 SDK 变慢时，如何隔离抓拍接入、比对和告警推送？
5. 现场机器有 50+ 台，如何定位是全局问题还是单节点问题？
6. 你亲自处理过的真实故障是哪一次？时间线、根因、止血、长期修复分别是什么？

**合格特征**：回答包含观测、定位、止血、验证和复盘；能用真实故障支撑，而不是只背 MQ 可靠性术语。
