# 高压追问面试题补充设计

## 目标

在现有《高宇-NL2DSL简历面试官追问清单.md》后补充一章高压追问题，帮助候选人在面试中应对真实性核验、项目边界、指标可信度、AI 辅助开发掌握度、生产落地边界等容易被问穿的问题。

## 范围

本次只补充面试官追问清单，不直接扩写完整参考答案。题目应围绕简历中已经出现的经历和技术点展开，避免引入新的项目经历、无法证明的指标或额外技术栈。

新增内容建议放在追问清单末尾，章节名为“十一、高压追问与防穿帮问题”。

## 内容结构

新增章节按风险点分组，每组包含三类内容：

1. 高频高压问题：面试官可能直接抛出的尖锐问题。
2. 连环追问链：围绕同一个风险点连续追问 4 到 8 个问题，模拟压力面。
3. 回答底线：提示哪些内容不要硬编，哪些边界需要主动说清。

建议分组：

- 项目真实性与边界：公司项目、个人开源项目、抽象复现之间的关系。
- Vibe Coding 掌握度：AI 辅助开发中本人负责的设计、Review、测试和取舍。
- 性能指标可信度：800ms 到 80ms、成本下降 90%、准确率 90% 等数据的来源和口径。
- RAG 与向量库选型：Milvus Lite、Qdrant、Elasticsearch、关键字检索、Rerank 的边界。
- 大数据与 Spark 真实性：元数据加工平台、Spark SQL 任务、表结构、调优案例是否能讲细。
- 代码现场讲解：能否打开 GitHub，按模块讲清核心链路和关键代码。
- 生产落地边界：Demo、开源验证、内部工具、生产系统之间的说法边界。
- Java 后端基本盘：避免被认为只会包装 AI 项目，保留后端稳定性经验的压测追问。

## 写作原则

- 问题要像真实面试官追问，语气可以尖锐，但不做无意义攻击。
- 每组题目要能验证一个明确风险点，不堆重复问题。
- 对明显敏感或无法证明的内容，回答底线应提醒“按真实情况说”。
- 尽量使用简历和现有文档中的术语：NL2DSL、DSL 校验、LangGraph、RAG、Milvus Lite、BGE-Reranker、Spark SQL、RabbitMQ、Arthas。
- 不新增完整答案，避免和参考答案文档大面积重复。

## 验收标准

- 新增章节能覆盖至少 8 个高压风险点。
- 每个风险点至少有 5 个问题，重点风险点包含连环追问链。
- 每组都有简短回答底线。
- 不引入与简历不一致的新事实。
- 文档结构与现有追问清单风格保持一致。
