# 2026-10-13 NL2DSL 面试训练复盘与 SQLBuilder 专项

> 本文汇总今天的对话与代码核查结果。它用于学习和校准简历口径，不是可直接背诵的公司项目履历。公开代码能证明开源版本的行为，不能单独证明个人在公司内部的职责。

## 今天确认了什么

| 主题 | 当前能确认的内容 | 尚需本人核实 |
| --- | --- | --- |
| 公司版与开源版 | 用户描述：开源 NL2DSL 基于公司内部版本；业务数据改用模拟数据；公司内治理配置来自 API，开源版改用 YAML | 代码是否复用、公开方式、公司内具体接口与上线范围 |
| 个人角色 | 曾提到“构建模块是我写的，测试验收”；随后又表示“其实啥也不懂” | “构建模块”具体指什么、亲手交付和测试验收的真实范围 |
| 开源版指标 | `configs/metrics.yaml` 中 `sales_amount` 对应 `SUM(order_amount)` | 公司版“销售额”指标的真实字段和口径 |
| 配置更新 | 开源版在组件构建时加载 YAML，RAG 索引在启动同步时按文件修改时间检查更新 | 公司治理 API 的刷新、缓存、版本与回滚机制 |
| SQL 构建 | 开源版有 `nl2dsl/sql_engine/builder.py`，接收 DSL 与注册配置，生成 SQL 字符串 | 公司版相应模块是否由本人开发、设计决策与测试证据 |

**口径冲突需要先解开：** 简历写“个人开源实现”和“负责核心架构设计与实现”；今天的描述又提到“内部版本的开源版”和对开发细节不熟。面试前应按事实确定公开版的代码来源、个人贡献与公司职责。不要把“能讲公开代码”直接等同于“独立完成公司核心模块”。

## 一、公司版与开源版：面试官怎么问

**面试官：两个版本是什么关系？**

**可说：** “它们面向同一类智能问数问题。公司内治理配置通过 API 获取；公开版用 YAML 配置替换这项依赖，并用模拟数据演示查询链路。”这只涵盖已提供的信息。

**追问：开源代码是公司正式公开、授权整理，还是个人重新实现？**

**当前回答：** “这项关系我需要核实后准确说明。”不能仅凭 GitHub 仓库或相似架构推断。面试现场应给明确事实，不要把三种情况混说。

**追问：公司项目中你负责哪一块？**

**答题框架：** “我负责`[真实模块]`，上游是`[提供输入的人或系统]`，下游是`[消费输出的模块]`；我亲手完成`[代码/设计/测试/联调]`，由`[真实验收方]`验证`[真实场景]`。”方括号不能凭公开代码补成公司事实。

**追问：你说‘核心开发’，怎么证明？**

**答题框架：** 讲一个需求的时间线、接口或对象结构、自己做的关键判断、一次失败或返工、交付后的验收。不能公开内部代码时，也能用脱敏的输入输出与测试思路解释；只有架构图和技术名词不够。

更多真实性连环追问见[面试官自问自答与连环追问](高宇-NL2DSL面试官自问自答与连环追问.md)的“真实性专项”。

## 二、治理配置变化：今天的深挖题

**面试官：治理服务改了‘销售额’口径，查询立刻生效吗？**

**开源版回答：** `nl2dsl/engine.py` 构建服务时读取 `metrics.yaml`，将注册配置交给校验器、语义解析器和 SQLBuilder；已构建的组件不会因 YAML 文件编辑而自动重新加载。`nl2dsl/rag/sync.py` 在启动同步时比较文件 `mtime` 与上次同步状态，检测到变化会 upsert 到向量集合。所以需要重新构建服务并触发索引同步，不能说“改完 YAML 立刻热更新”。

**追问：注册表与索引版本不一致怎么办？**

**开源版回答：** 当前加载与同步不是原子发布。同步失败时 `engine.py` 记录警告并继续构建，检索上下文可能旧、执行侧注册配置可能新。对于同名指标，upsert 使用稳定 ID 更新；删除指标时，当前同步流程没有自动清除旧向量的步骤。

**追问：生产上怎么设计？**

**设计回答：** 给配置和索引同一个不可变版本，构建新索引并跑样例回归，再原子切换查询所用版本；单次请求绑定同一版本，失败可回滚。这个是建议方案，不能说成开源版或公司版已实现。

**代码定位：** `nl2dsl/semantic/registry.py`、`nl2dsl/engine.py`、`nl2dsl/rag/sync.py`、`nl2dsl/rag/store.py`。

## 三、SQLBuilder 用一句话讲懂

`SQLBuilder` 是 **DSL 到 SQL 的确定性构建器**：输入已生成的 DSL 和注册配置；确定数据源对应的物理表，解析维度与指标，补必要的 JOIN，构建 WHERE、GROUP BY、HAVING、ORDER BY、LIMIT/OFFSET；输出 SQL 字符串。它不负责理解自然语言，也不直接执行查询。

当前开源代码入口是 `nl2dsl/sql_engine/builder.py:403` 的 `build(dsl)`。SQL 生成后在 Graph 中还会流经 `scan_sql → sandbox_check → execute_sql`；构建成功不等于已通过权限、安全或性能检查。

### 从一个例子理解输入输出

用户问：“华东地区销售额最高的 5 个商品。”DSL 大致包含 `data_source=orders`、指标别名 `sales_amount`、商品维度、地区过滤、销售额降序和 `limit=5`。配置里 `orders` 映射物理表，`sales_amount` 映射聚合表达式，`region` 的 `value_map` 把业务值“华东”映射为编码 `HD`。最后构建出含聚合、过滤、分组、排序和限制的 SQL。**这只是开源样例，不是公司真实业务数据。**

## 四、SQLBuilder 连续追问与回答

**面试官：模块输入、输出分别是什么？**

**回答：** 输入是 `DSL` 对象以及构造器持有的表映射、维度映射、注册指标、取值映射和数据库元数据；输出是按当前数据库方言编译的 SQL 字符串。`DSL` 的结构定义在 `nl2dsl/dsl/models.py`。

**追问：为什么 SQLBuilder 要先找到主表？**

**回答：** `dsl.data_source` 是语义名称，构建器用 `table_mapping` 找物理表，再从 SQLAlchemy 反射的元数据中取表对象。表不存在时抛校验异常，而不是猜表名继续执行。参见 `builder.py:403` 起的 `build`。

**追问：模型说销售额要 `SUM(discount_amount)`，会错算吗？**

**回答：** 当指标别名 `sales_amount` 在注册表中存在，`_metric_expr` 先取注册表达式，例如 `SUM(order_amount)`，构建查询字段时优先用它，忽略 DSL 中模型猜的物理字段。注册配置决定口径；模型负责选择要查哪个指标。参见 `builder.py:42` 与 `builder.py:464`。

**追问：用户说‘华东’，物理库里是 `HD`，在哪儿转换？**

**回答：** `_translate_filter_value` 读取维度的 `value_map`，构建叶子过滤条件时先把语义值映射成物理值，再做类型对齐。参见 `builder.py:181`、`builder.py:199`，映射样例在 `configs/metrics.yaml`。

**追问：为什么有 GROUP BY 和 ORDER BY？**

**回答：** 同时查询维度和聚合指标时，按维度分组；按指标别名排序时，构建器会把排序字段解析为真实列或指标别名；有 `limit` 且无结果后处理时才在 SQL 中应用全局 LIMIT，避免破坏按组 TopN 或占比的结果。参见 `builder.py:513` 与 `builder.py:560` 后的逻辑。

**追问：SQLAlchemy 已经帮你构建 SQL，就能保证安全了吗？**

**回答：** 不能。SQLBuilder 解决结构化构建和部分字段校验；Graph 后续还有 `SQLScanner` 与 `QuerySandbox`。当前扫描器只覆盖某些危险模式，沙箱的 SQLite 扫描行数也是启发式估算。权限与数据库只读账号等仍需要独立防线。

**追问：如果现场让你修改 SQLBuilder，你第一步做什么？**

**回答：** 先确认输入 DSL 和注册配置是否已有表达能力，再读 `build` 的对应分支和相关测试；新增需求要同时考虑指标口径、维度映射、过滤、排序以及失败路径。先写一个可复现样例，再做最小改动并回归。若从未亲手改过此模块，应说“我能按代码分析修改路径”，不说“我以前就是这样改的”。

## 五、把“懂代码”与“亲手开发”分开

今天已经可以从公开代码学会解释 SQLBuilder 的职责和数据流；这与能否在公司简历中写“我开发了 SQL 构建模块”是两个不同问题。

面试前为这个模块填完以下五格：

1. 我开发的是公司版还是公开版？公司版真实模块名是什么？
2. 我亲手写过哪些接口、函数、测试或设计文档？
3. 需求由谁提出，上游配置由谁提供，下游由谁消费？
4. 测试验收具体测了哪三类查询或失败场景？验收人是谁？
5. 有无可公开或可脱敏说明的提交、任务单、测试报告或故障复盘？

如果这些问题暂时答不上来，可在面试中说明“我熟悉公开版 SQL 构建链路，正在核实自己在公司侧的交付范围”，并相应收窄简历措辞。不要把学习后的理解冒充历史贡献。

## 六、接下来怎么练

先自己回答“四、SQLBuilder 连续追问”的前两题，控制在每题 30～60 秒；再打开 `builder.py` 指出对应位置。能够独立讲清输入输出、注册口径、失败路径后，再练权限与配置版本；公司侧角色事实留待本人核实。
