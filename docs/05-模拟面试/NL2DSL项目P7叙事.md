# NL2DSL 项目 P7 叙事（30 秒 / 2 分钟 / 10 分钟）

> **这份文档解决什么问题**：同一个项目，讲成 P6 还是 P7，薪资差 30%。
>
> **用法**：三个版本全部背到能脱口而出；注意每版的"停顿点"——那是留给面试官追问的地方，也是你控制节奏的抓手。
>
> **铁律**：所有数字都要能解释来源。估的就说"按每人天 X 元估算"，不能编。

---

## 0. 先说清 P6 和 P7 的根本区别

### 同一句话的两种讲法

| | 讲法 |
|---|---|
| **P6** | "我做了一个 NL2DSL 系统，基于 LangGraph 设计了 16 个节点，包含校验、权限、SQL 构建，还建了评测体系。" |
| **P7** | "我发现'让大模型直接写 SQL'在企业里根本交付不了——不可校验、权限失控、审计不了。所以我把架构拆成两层：模型只出 DSL，执行交给系统。这个取舍决定了项目能不能过甲方的安全审查。" |

### 结构差异

| 维度 | P6 | P7 |
|---|---|---|
| 开场 | 我做了什么 | **我发现了什么问题** |
| 主体 | 系统有哪些模块 | **我否掉了什么、为什么这么选** |
| 落点 | 技术指标 | **业务后果（能不能交付 / 省多少）** |
| 隐含信息 | "我能干活" | **"我能拍板"** |

> 高薪岗位招的是**能拍板的人**。拍板的证据不是"我实现了"，是"我否掉了什么"。

---

## 一、30 秒版

**用在哪**：自我介绍、HR 初筛、"简单介绍下你最近的项目"

### 逐字稿

> "我这三年主要做企业级 AI 问数系统。
>
> 核心判断是：**让大模型直接生成 SQL，在企业里走不通**——不可校验、权限失控、审计不了，项目过不了甲方的安全审查。
>
> 所以我把架构拆成两层：模型只输出结构化的 DSL，执行交给系统。这个取舍牺牲了模型的自由表达，换来可校验、可审计、可归因。
>
> 现在业务取数从 3 天缩短到 3 分钟。"

### 这段话埋了什么

```
① "核心判断"         → 我在拍板，不是执行
② "走不通"           → 我否掉过方案
③ "牺牲…换来…"        → 我懂取舍
④ "3 天 → 3 分钟"     → 钱的语言
```

**长度控制**：约 150 字，正常语速 25–30 秒。

---

## 二、2 分钟版

**用在哪**：业务面 / 技术面开场，"详细讲讲这个项目"

### 逐字稿

> **【背景 20 秒】**
> "我在国网的数据治理团队做 AI 问数系统。业务侧的痛点是：业务人员看不懂表结构，取数要提工单排期，平均 3 天；数据团队大量时间在做'人肉查询接口'。
>
> **【试错 30 秒】**
> 第一版我们让大模型直接写 SQL。Demo 跑得通，一上生产就崩：模型会编不存在的字段、绕过行级权限、生成全表扫描，而且出了问题没法归因——是理解错、生成错、还是执行错？甲方安全审计这一关直接过不了。
>
> **【判断 40 秒】**
> 我当时判断：问题不在模型能力，**在于我们把'决策'和'执行'耦合在一起了**。
> 所以我中间插了一层 DSL 当契约：模型只负责'想查什么'——选哪个指标、按什么维度、什么过滤条件；系统负责'怎么安全地查'——校验、权限、构建 SQL、扫描执行。
>
> **【取舍 20 秒】**
> 这个取舍的代价是牺牲模型的自由表达——它不能随便写复杂逻辑了；换来的是三个能力：**可校验**（DSL 有白名单）、**可审计**（每一步有 trace）、**可归因**（错在哪一环能定位）。
>
> **【落地 10 秒】**
> 落地时我设计了五道闸门：结构校验、语义校验、权限注入、SQL 安全扫描、沙箱预检，再加一层人工复核兜高风险查询。
>
> **【结果 10 秒】**
> 结果就是这个系统过得审计、能交付。业务侧取数从 3 天到 3 分钟。"

### 停顿点（重要）

| 讲完这段 | 停 1 秒，等对方接 |
|---|---|
| "过不了安全审计" | 大概率问"为什么过不了" → 你可以展开权限和归因 |
| "插一层 DSL 当契约" | 大概率问"为什么用 DSL 不用直接 SQL" → 你的强项 |
| "五道闸门" | 大概率问"具体哪五道" → 展开你的实现 |
| "3 天到 3 分钟" | 大概率问"怎么算的" → 用第四节的数字备用包 |

**别一口气讲完不给对方插嘴的机会**——那不叫流畅，叫背稿。

## 三、10 分钟版

**用在哪**：总监面、架构深挖、"画一下你的系统"

### 六段结构

| 段 | 时长 | 内容 | 目的 |
|---|---|---|---|
| ① 问题 | 1.5 min | 业务痛点 + 第一版为什么失败 | 建立"我懂业务" |
| ② 判断 | 2 min | 三个方案的对比 + 我否掉了什么 | 建立"我能拍板" |
| ③ 架构 | 3 min | 双层架构 + 五道闸门（可画图） | 建立"我能落地" |
| ④ 质量 | 1.5 min | 评测体系 + 为什么不用模型判分 | 建立"我讲证据" |
| ⑤ 结果 | 1 min | 业务价值 + 三个数字 | 建立"值多少钱" |
| ⑥ 边界 | 1 min | 我明确没做的 + 下一步 | 建立"我诚实" |

### ① 问题（1.5 分钟）

```
业务侧：取数靠工单，3 天；数据团队 60% 时间在回答重复问题
技术侧第一版：LLM 直接生成 SQL
  → 编字段、绕权限、全表扫、不可归因
  → 安全审计过不了 = 项目交付不了
```

### ② 判断（2 分钟）——**这是 P7 的核心段落**

把当时的三条路摆出来：

| 方案 | 为什么否掉 / 选它 |
|---|---|
| **微调模型让它"更会写 SQL"** | 解决不了权限和审计问题，而且换个客户就要重训 |
| **让 Agent 自主调用 SQL 工具** | 决策和执行耦合，模型可以绕过校验；出问题无法归因 |
| **✅ 插入 DSL 契约层** | 把"决策"和"执行"分开，中间这一层可以校验、注入权限、留痕 |

**这段必须有"我否掉了什么"**，否则听起来像"别人让我这么做的"。

### ③ 架构（3 分钟，可以画图）

```
用户问题
   ↓
Agent 层（LLM 参与）     意图识别 · 复杂问题拆解 · 子查询调度
   ↓
DSL（契约层）            ← 关键设计：模型只输出这个
   ↓
Graph 层（LLM 不执行）
   五道闸门：结构校验 → 语义校验 → 权限注入 → SQL 扫描 → 沙箱预检
   ↓
执行 + 审计
```

**画图时讲的两个重点**：

1. **DSL 里只有"业务语义"**——指标、维度、过滤、排序，没有表名、没有 SQL 片段。所以模型没有机会注入。
2. **每一道闸门都能独立拦截**，不是一次性打包校验——这样出问题能定位到具体环节。

### ④ 质量（1.5 分钟）

```
为什么不用 LLM 当裁判判分？
→ 不可复现、不可做门禁
   ↓
我的做法：canonical 规范化 + 二元判定（对/错，没有 0.87 分）
   ↓
再加回归门禁：数据集指纹 + 维度阈值 + 非零退出
```

**这一段的价值**：证明你懂"评测的可信度"比"评测的分数"重要。

### ⑤ 结果（1 分钟）——用钱的语言

| 技术表述 | 换成 |
|---|---|
| DSL 校验通过率 95% | 生成的查询 95% 一次通过，不用反复改 |
| 取数 3 天 → 3 分钟 | **10 人数据团队年省约 2000 人天**（按每人天 500 元估算，约 100 万） |
| 通过安全审计 | **项目能交付**——这是从"不能用"到"能用"的开关 |

### ⑥ 边界（1 分钟）——**这段最加分**

> "三块我明确没做：一是多轮对话，现在还是单轮；二是工具调用，元数据类工具我设计了但没落地；三是原生数仓对接，我只做过 MySQL，Hive/Doris 知道怎么改但没实操过。
> 这三块的优先级我排过：工具调用最急，因为它决定我的 Agent 是'编排型'还是'自主型'。"

**主动划边界，比假装全能更容易被信任。**

## 四、数字备用包（每个都要能解释来源）

| 数字 | 怎么来的 | 被追问时怎么答 |
|---|---|---|
| **取数 3 天 → 3 分钟** | 工单排期对比即席查询 | "3 天是原来提工单到拿数的平均周期，3 分钟是现在端到端时间" |
| **年省 2000 人天** | 10 人团队 × 每人每天约 1 次取数 × 200 工作日 | "按 10 人团队、每人每天一次取数估的，实际可能更多" |
| **50 例全量 69.7%** | 评测报告实测 | **主动说**："这是全量数据，不是最好的那个子集" |
| **10 例子集 86.9%** | 同一份报告 | "子集波动大，所以我更认 50 例那个数" |
| **16 个节点** | 代码里 `add_node` 的数量 | 实打实，可以翻代码 |

> **诚实处理**：69.7% 这个数字不好看，但**主动说出来反而加分**——它证明你不挑数据。真的被问"为什么不高"，答："小样本 + 长尾查询，主要卡在多表 join 和术语歧义，这是我下一步要优化的方向。"

## 五、讲的时候的节奏

| 版本 | 语速 | 停顿 | 禁忌 |
|---|---|---|---|
| 30 秒 | 正常，略快 | 讲完"3 天到 3 分钟"停住 | 不要补充技术细节 |
| 2 分钟 | 慢一点 | 每个"钩子"后停 1 秒 | 不要一口气不喘 |
| 10 分钟 | 平稳，可画图 | 每段结束问"这块要展开吗" | 不要念 PPT |

**一个技巧**：10 分钟版每段结束问一句"这块要展开吗？"——**把控制权交给对方，同时显得你有货可讲**。

---

## 六、最容易跑偏的四个地方

| 跑偏 | 表现 | 纠正 |
|---|---|---|
| **滑回 P6** | 开始讲"我用了 LangGraph、FastAPI、Milvus…" | 技术栈只在被问时答，开场永远讲问题 |
| **只讲成功** | 不提第一版失败 | 失败的那版是**最有说服力的部分**（证明你真做过） |
| **堆术语** | "canonical 规范化""二元判定" | 先讲人话，术语作为括号补充 |
| **不敢说边界** | 什么都说"我们也做了" | 明确说"三块没做"，并给出优先级 |

## 七、追问预判（每个版本后面接什么）

### 30 秒后最可能被问

> **"为什么企业里不能直接用大模型生成 SQL？"**

答（3 句）："四个问题：它会编不存在的字段；它能绕过行级权限；它会生成全表扫描；出了错分不清是理解错还是执行错。这四条任意一条在甲方那里都是否决项。"

### 2 分钟后最可能被问

> **"DSL 具体长什么样？"**

答（画一个）：

```json
{
  "data_source": "orders",
  "metrics": [{"alias": "gmv"}],
  "dimensions": ["region"],
  "filters": [{"field": "region", "operator": "in", "value": ["华东"]}],
  "limit": 100
}
```

然后补一句："注意这里**没有表名、没有 SQL 片段**，物理映射都在注册表里——所以模型没有注入的机会。"

### 10 分钟后最可能被问

> **"如果让你重做一遍，你会改什么？"**

答（诚实 + 有判断）：

> "两件事。第一，我会一开始就建评测集——我中途才建，导致前面改了很多次都是凭感觉。第二，我会把工具调用做进第一版，让模型能自己确认'这个维度存不存在'，而不是等校验失败再修。这两个都是我现在的最高优先级。"

---

## 八、一句话总结

> **P6 讲"我实现了什么"，P7 讲"我判断了什么、否掉了什么、这些判断让项目怎么了"。**
> 同一个项目，换个讲法，价格不一样。
