# 高薪作战手册（标签 · 数字 · 简历 · 议价）

> **前提**：技术能力决定你能不能进面试，**这份文档决定你最后拿多少钱**。
> **用法**：标签和三个数字背熟；简历按第七节逐条改；议价和反问面试前 10 分钟过一遍。
> **铁律**：所有数字都要能解释来源，标了【填】的需要你补真实值。

---

## 一、先看清：薪资由四个变量决定

```
薪资 = 岗位带宽 × 简历通过率 × 定级表现 × 议价能力
```

| 变量 | 你能控的部分 | 你现在的状态 |
|---|---|---|
| **岗位带宽** | 投什么岗位 | ⚠️ 一直投执行岗，带宽天然低 |
| **简历通过率** | 简历写法 | 🟡 技术密度够，但缺成果量化 |
| **定级表现** | 面试叙事 | 🟢 已有 P7 叙事文档 |
| **议价能力** | 流程与话术 | 🔴 完全没准备 |

**这份手册补的是第 1、2、4 项。**

---

## 二、一句话标签：让人记住你是"哪一种"

高薪岗位会问"你和别人有什么不同"。**没有标签 = 默认按"又一个 8 年后端"定价。**

### 三个候选（按岗位选）

| 标签 | 适合投什么 |
|---|---|
| **A.「懂数据治理的 AI 应用架构师——把不可控的大模型，做成过得了审计的企业级问数系统」** | 技术负责人 / 架构岗 / 甲方数据部门 |
| **B.「从 0 到 1 落地过企业级 NL2DSL：用 DSL 契约把大模型关进可校验的笼子里」** | 纯 Agent 开发岗 / AI 应用团队 |
| **C.「AI + 数据双栖：既懂指标口径治理，也懂 Agent 编排落地」** | 数据平台 / 数据智能岗 |

### 标签要满足三条

```
① 一句话说完（20 字内最理想）
② 有反差或稀缺性（"懂治理的 AI 人"比"会写 Agent 的人"稀缺）
③ 能被证据支撑（你说的每一部分，简历里都有对应条目）
```

**默认用 A**——它把你的三块经历（Java 后端 / 数据治理 / AI 应用）压成了一个点。

### 标签用在哪

| 场景 | 怎么用 |
|---|---|
| 自我介绍第一句 | "我是做企业级 AI 问数系统的，简单说就是——把不可控的大模型做成过得了审计的系统。" |
| 简历标题 | 高宇 \| AI 应用架构师（Agent + 数据语义层）\| 8 年 |
| 和 HR 沟通 | "我主要做 AI 应用架构，特别是数据方向的。" |
| 反问环节 | "这个岗位更看重 Agent 能力还是数据能力？"（暗示你两样都有） |

## 三、商业价值：必须能报出三个数字

技术面试官看能力，**总监和 HR 看价值**。高薪卡在总监那一关，所以必须会翻译。

### 翻译公式

```
技术指标 → 人力/时间/风险 → 钱
```

### 你的三个数字

**① 人力：取数从 3 天 → 3 分钟**

```
原来：业务提工单 → 排期 → 数据同学写 SQL → 3 天
现在：自然语言即席查询 → 3 分钟
换算：10 人数据团队 × 每人每天 1 次取数 × 200 工作日 ≈ 2000 人天/年
按 500 元/人天估 ≈ 100 万/年
```

**② 速度：复杂问题并行拆解**

```
"对比华东华南趋势"原本串行查 3 次
现在拆成子查询并行，端到端约 1/3
```

**③ 风险：把事故挡在发布前**

```
五道闸门 → 越权查询在 DSL 层就被拦下
评测门禁 → 改坏了上线前非零退出
价值：一次数据泄露事故的代价（罚款 + 客户信任 + 返工），远高于系统投入
```

### 话术（30 秒）

> "直接的价值是取数效率：从 3 天到 3 分钟，按 10 人数据团队算，一年大概省 2000 人天。
> 但更关键的是**能不能交付**——没有 DSL 这层契约，甲方安全审计过不了，这个系统就上不了线。所以我的工作本质是把'不能用的 AI'变成'能签合同的系统'。"

> **注意**：说"按 X 估算"而不是"就是 X"。**能解释来源的数字才有说服力。**

## 四、简历：从"职责体"改成"成果体"

### 改法三原则

| 原则 | 说明 |
|---|---|
| **每条前面加动词** | 主导 / 设计 / 落地 / 把 XX 从 A 改到 B |
| **每条后面加括号量化** | （16 节点 / 95% 通过 / 3 天→3 分钟） |
| **技术名词后面跟一句"所以呢"** | 不是"用了 DSL"，是"用 DSL 让查询可校验" |

### 标题与个人信息

| 现在 | 建议 |
|---|---|
| 高宇 - AI Agent / NL2DSL / 大数据（语义层治理） - 8年 | **高宇 \| AI 应用架构师（Agent + 数据语义层）\| 8 年** |

| 现在 | 改成 |

| 具备为 AI 应用建设数据底座的能力… | **AI + 数据双栖**：既能设计 Agent 链路，也能用 Spark 把表/字段/指标加工成 AI 可消费的语义层。 |
| 具备AI辅助开发与Vibe Coding实践经验… | 用 AI 辅助开发把一个万行级项目从 0 推到可用（700+ 测试用例），单人不增编。 |
| 熟悉从业务需求…完整工程闭环 | 保留，压短。 |

### 核心职责逐条改写（NL2DSL 项目）

**第 1 条（架构决策，最重要）**

```
现在：负责NL2DSL核心架构设计与实现，将"LLM直接生成SQL"改为"LLM生成结构化DSL，系统负责校验、治理和SQL构建"，用DSL作为语义契约承接指标、维度、过滤条件、排序、分页和后处理。

改成：主导架构决策——把"LLM 直接生成 SQL"改为"LLM 只出结构化 DSL，系统负责执行"，
      用 DSL 作为语义契约承接指标/维度/过滤/排序。该决策让查询从"不可校验"
      变成"可校验、可审计、可归因"，是项目通过甲方安全审查、
      从 demo 走向可交付的前提。
```

**第 2 条（Vibe Coding，应弱化）**

```
现在：在个人开源实现中采用Vibe Coding方式推进开发…

改成：以 AI 辅助开发推进从 0 到 1 的实现（方案拆解/代码生成/单测补齐由 AI 起草
      + 人工 Review），独立完成万行级代码与 700+ 测试用例。
```

**第 3 条（节点数）**

```
现在：基于LangGraph设计10+节点查询管道，覆盖…

改成：基于 LangGraph 设计 16 节点查询状态机（含校验、权限 2 个子图），
      把单次问数拆成 13 个可独立拦截的环节；每节点输出结构化 trace，
      支撑按 query_id 定位到具体失败环节。
```

**第 4 条（双层架构）**

```
现在：设计Agent层与Graph层双层架构…

改成：设计 Agent 层 + Graph 层双层架构：Agent 层做意图识别与子查询并行调度
      （asyncio + 信号量限流 + 依赖串行），Graph 层保证单查询从 DSL 到 SQL 的
      确定性链路。复杂问题拆解并行后，端到端耗时约为串行的 1/3【填实测】。
```

**第 5 条（语义层，必须突出"机制"）**

```
现在：设计语义层治理模型…

改成：设计语义层治理模型：把"销售额/华东/近7天"映射为指标口径、字段映射与值域编码。
      关键设计是"指标只存 alias，物理表达式由注册表权威下发，模型猜测的字段会被忽略"
      ——从机制上消除口径漂移，而不是靠 prompt 让模型别乱写。
```

**第 6 条（检索）**

```
现在：设计Milvus Lite + 关键词检索 + MySQL的混合检索…

改成：设计四集合检索（schema/metrics/terms/history）：短实体走 jieba 关键词 +
      向量双通道，长文本历史走整句语义；再叠一层本地 Cross-Encoder 精排，
      配合阈值过滤与空召回回退，让 4000 字符上下文预算全用在有效信息上。
```

**第 7 条（权限，强调"模型视野之外"）**

```
现在：实现DSL层权限控制与安全防线…

改成：在 DSL 层实现两级权限——行级过滤注入（tenant_id + 用户数据域）+ 列级敏感
      字段检查，SQL 执行前再叠安全扫描与沙箱预检。权限在模型视野之外注入，
      提示词无法绕过。
```

**第 9 条（评测，主动给真实数字）**

```
现在：建设自动化评测体系，围绕Semantic、Planning、Execution、Governance四类指标…

改成：建设 4 类 12 维自动化评测 + 回归门禁（数据集指纹 + 维度阈值 + 非零退出），
      把"改坏了上线"挡在发布前。50 例全量基线 69.7%，据此定位出多表 join 与
      术语歧义是两个主要瓶颈，作为下一阶段优化目标。
```

> **主动写 69.7%**——诚实本身就是稀缺品质，而且面试官一定会追问"为什么不高"，你正好有答案。

**第 10 条（审计）**

```
改成：建设节点级 trace + 审计台账（DSL/SQL/耗时/错误码/扫描行数），支持按 query_id
      定位失败环节；审计查询的租户过滤下沉到 SQL 层，跨租户记录返 404 而非 403，
      不泄露存在性。
```

## 五、投递策略：决定薪资带宽

### 岗位分层（按薪资天花板排）

| 层级 | 岗位名称 | 薪资天花板 | 你的匹配度 |
|---|---|---|---|
| **1** | AI 应用架构师 / 技术负责人 | 最高 | 🟢 有架构经历 |
| **2** | AI 应用高级开发（Agent 方向） | 高 | 🟢 完全对口 |
| **3** | 数据智能 / ChatBI 方向高级开发 | 中高 | 🟢 最对口 |
| **4** | 数据平台 / 数据治理 + AI | 中 | 🟡 可投 |
| **5** | 外包 / 驻场开发 | 低 | ❌ **不要投**（你现在就在这层） |

**关键**：**不要在同一层里平移**。你现在最可能犯的错是"投一个薪资高 10% 的外包"，那只是换个地方做同样的事。

### 公司类型选择

| 类型 | 优点 | 缺点 |
|---|---|---|
| **甲方的数据/数字化部门**（国网、银行、运营商） | 稳定、认你的行业经验、看重治理能力 | 涨薪慢、流程长 |
| **BI / 数据厂商**（帆软、观远类） | 完全对口、能带产品视角 | 薪资中等 |
| **AI 创业公司** | 薪资弹性大、给 title | 不稳定、强度高 |
| **大厂（外包岗 vs 正式岗）** | 平台背书 | 正式岗对学历卡得紧 |

**建议组合**：甲方 2 家 + BI 厂商 2 家 + 创业 2 家 + 大厂 1 家 = 7 家起投。

### 时间窗口

```
金三银四（3–4 月）：岗位最多，竞争也最激烈
金九银十（9–10 月）：次高峰
年底（12–1 月）：岗位少，但竞争者更少，容易谈条件
```

## 六、议价：8 条硬规矩

| # | 规矩 | 说明 |
|---|---|---|
| 1 | **不先报期望薪资** | 反问你："这个岗位的带宽是多少？" |
| 2 | 被逼报就报区间 | "我目前看 30–35 这个区间"（区间下限 = 你的真实目标） |
| 3 | **谈总包不谈月薪** | base / 绩效 / 年终 / 签字费 / 股票，逐项问清 |
| 4 | **并行 2–3 个流程** | 单 offer 没有议价权，这是物理规律 |
| 5 | 用"我不着急"造时间 | "我在看机会，还没有到决策期" |
| 6 | **不接受降级定级** | "我不接受按下一级招进来，如果是这个定位我们就别浪费彼此时间" |
| 7 | 拿到书面 offer 再谈 | 口头承诺不算数 |
| 8 | 离职原因永远向前看 | 不说前公司坏话，只说"想找更大的技术挑战" |

### 三个高频谈薪场景 + 话术

**场景 1：HR 问"你现在多少"**

> "我现在的包不方便细说，但我这次的预期是基于市场和我能带来的价值——我更想先了解这个岗位的定位和带宽。"

**场景 2：HR 说"我们最多给到 X，比你预期低"**

> "理解。如果 base 卡在这个数，我想看看绩效和年终的结构，以及定级能不能往上走一级——我上一份工作是从 0 到 1 主导架构的，给下一级我担心发挥不出来。"

**场景 3：拿到 A 家 offer，想抬 B 家**

> "我这边已经有一个 offer 在手上，但我更倾向你们——如果薪资能对齐到 X，我可以直接定。"

> **注意**：用 offer 抬价要**真实**。编一个 offer 被识破，全盘皆输。

## 七、反问环节：15 个问题，分四类

**反问不是走过场，是最后一次抬定级的机会。**

### 技术类（显示你想落地）

```
1. 这个岗位现在最大的技术难题是什么？
2. 团队现在 Agent 的形态是编排型还是自主型？
3. 数仓那边是哪个引擎？数据和 AI 的边界怎么划？
4. 效果评估现在做到什么程度了——有没有评测集和门禁？
```

### 团队类（显示你想协作）

```
5. 团队现在多少人？AI 和数据分别几个人？
6. 这个岗位汇报给谁？
7. 产品和算法同事的协作方式是什么？
```

### 业务类（显示你想清楚价值）

```
8. 这个系统现在服务多少业务方？主要解决什么场景？
9. 公司对这块的期待是什么——降本还是增收？
10. 上线节奏是怎样的，第一个里程碑在什么时候？
```

### 风险类（显示你成熟）

```
11. 这个岗位是新增还是补缺？如果是补缺，前一位为什么离开？
12. 团队现在最缺的能力是什么？
13. 如果我进来，前三个月最需要解决哪件事？
```

### ❌ 不要问

```
薪资多少（HR 环节问，技术面不问）
加班多吗（换成"团队的交付节奏是怎样的"）
公司稳定吗（敏感）
```

## 九、六个最常见的翻车点

| 翻车 | 后果 | 避免 |
