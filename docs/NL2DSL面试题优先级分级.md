# NL2DSL 面试题优先级分级

> 基于《NL2DSL 项目必学知识点与高频面试题》重新分级。
> 判断标准：**面试官不看源码、仅凭简历 + 通用岗位要求，会不会主动问。**
> 会主动问 = 真高频；要靠读你源码才知道 = 深挖自检；标了【设计题/代码题】= 第三梯队。

---

## 分级速览

| 梯队 | 定位 | 数量 | 价值 | 投入 |
|------|------|------|------|------|
| **第一梯队 真高频** | 面试官大概率主动问 | ~33 题 | 决定过不过 | 全部吃透，能白板 |
| **第二梯队 深挖自检** | 沿源码深挖才暴露 | ~26 题 | 防止露怯 | 每类抽 2-3 题口述 |
| **第三梯队 设计/代码题** | 考架构思路 | ~22 题 | 拉开差距 | 只练思路，明确"未实现" |

**一句话：先保证第一梯队白板过关，再用第二梯队查盲区，第三梯队是加分项不是及格线。**

---

## 第一梯队：真高频（必吃透）

> 面试官不读源码也会问的。分两类：① 简历亮点必被追；② 大模型应用后端通用考点。

### 简历亮点必被追（P0 六条 + 多域，这是地基）

| 题号 | 考点 | 为什么必问 |
|------|------|-----------|
| P0-1 | API 入口完整请求链路 | 简历写了"双层架构 Agent+Graph"，必让你画路径 |
| P0-2 | DSL 契约 vs Pydantic 边界 | 简历核心卖点"LLM 只生成 DSL"，必追问为什么 |
| P0-3 | SQLBuilder 怎么变 SQL | "指标/维度/值映射/JOIN/后处理"全是简历词 |
| P0-4 | LangGraph 节点与循环 | 简历写了"10+ 节点管道"，必问节点细节 |
| P0-5 | 行级/列级权限边界 | 简历写了"权限注入"，必问未配置用户、OR 语义 |
| P0-6 | 扫描/沙箱/执行三者职责 | 简历写了"SQL 安全扫描、沙箱预检"，必问区别 |
| P1-9 | 多域隔离与生产入口 | 简历写了"多域自治" |

### 通用考点（换个项目也会问）

| 题号 | 考点 |
|------|------|
| A-4 | 同名不同口径（销售额 vs GMV），实体提示 vs 注册表谁有最终解释权 |
| A-6 | "今年比去年增长"拆成什么子查询，时间基准/分母为零怎么表示 |

| B-18 | 两期只一期成功，能否输出增长率（防止部分结果被当完整结论） |
| D-31 | 指标从 YAML 删除后旧向量仍被召回，注册表能否兜住 |
| D-35 | Reranker 排第一但注册表里同名指标属另一数据源，谁拒绝 |

## 第二梯队：深挖自检（防露怯）

> 面试官得读过你源码才知道这些细节。价值是"他顺着某个点往下挖时你不卡壳"，不是"这些题会考"。
> **用法：每类抽 2-3 题口述，答不出就回去读对应函数，不逐题背。**

| 题号 | 考点 | 暴露风险 |
|------|------|---------|
| A-1 | 两次 route 结果不一致 | 你把 route 说错时会露怯 |
| A-2 | exploration 是否真执行探索循环 | 别把规划能力说满 |
| A-3 | 比较问题误判 single_query 怎么定位 | 排查思路题 |
| A-5 | depends_on 合法性在哪层验证 | 依赖校验边界 |
| A-8 | 跨 domain 复合查询能否支持 | 能力边界要诚实 |
| B-11 | MAX_PARALLEL_SUB_QUERIES 限制范围 | 并发语义 |
| B-13 | thread_id=f"sub_{id}" 碰撞 | 潜在 bug |
| B-14 | 子查询 query_id 传空字符串 | trace 关联缺口 |
| B-15 | 依赖返回 warning/clarification 下游怎么办 | 容错语义 |
| B-16 | 依赖环如何结束 | 边界处理 |
| B-19 | Aggregator 数值列启发式查找 | 聚合正确性 |
| C-21 | trace reducer 去重丢事件 | State 合并细节 |
| C-22 | 子图 trace 带回为何去重 | 同上 |
| C-23 | 校验失败避免带错误 DSL 继续 | 状态正确性 |
| C-24 | route_after_validate 双重上限 | 循环终止条件 |
| C-25 | 简化重试会否删掉用户要求的过滤/维度 | "重试成功仍回答原问题" |
| C-26 | detect_complexity 两标签都去 scan_sql | 误导性分支 |
| C-28 | 审批防重复/越权/过期 | resume 校验 |
| C-29 | resume 默认 query_graph 命中哪张图 | domain 恢复 bug |
| D-33 | jieba 词库何时更新 | 同步时机 |
| D-34 | 10 个关键词多少次向量调用 | 成本 |
| D-37 | RuleEngine 同优先级规则读到哪个版本 | 规则顺序依赖 |
| D-38 | dsl_before 浅拷贝 diff 失真 | 潜在 bug |
| D-39 | 规则异常转 Warn，本应拦越权 | fail-open/closed |
| D-40 | 记录每步修改理由/责任边界 | 可解释性 |
| F-52 | 两种流事件 schema 是否一致 | 前后端契约 |
| F-53 | SSE 异常后审计也失败怎么办 | 容错 |
| F-55 | resume 鉴权/审批人身份 | 安全缺口 |
| F-58 | 两条路径结果不一致比对什么 | 调试思路 |
| G-61 | 相对时间固定 reference_date | 评测稳定性 |
| G-65 | JOIN 推导最小回归集 | 工程变更 |

## 时间分配建议

1. **60% 时间** → 第一梯队 P0 六条，练到"白板 10 分钟画路径 + 现场 15 分钟手写 DSL→SQL + 每题说一个失败分支"。
2. **25% 时间** → 第一梯队通用考点（E 类安全题尤其重要，简历写了权限，面试官最爱压安全边界）+ 每类深挖题抽 2-3 道口述查盲区。
3. **15% 时间** → H-67 新业务域设计题，其余设计题只列框架。

**三条红线（贯穿所有梯队）：**
- 【设计题】一律说"我设计、尚未实现"，被追问"代码在哪"就指到设计文档，别说有。
- 数字（准确率、延迟）找不到原始评测输出就不报精确百分比，改说"约""量级"。
- 每道题的终点是"指到函数 + 输入输出 + 一个失败分支"，不是背定义。
