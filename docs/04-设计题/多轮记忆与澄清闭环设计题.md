# 多轮对话与澄清：面试官会怎么一路追问（未实现 · 问答版）

> **证据边界**：项目现在是**单轮**。
> - 一次查询开一个线程（`thread_id = query_id`），查完就结束，没有"同一个人还在聊"的概念。
> - 流程中间状态只在内存里（`InMemorySaver`），服务一重启就没了；而且一个线程只服务一次查询，下一轮不会复用。
> - 澄清是"问完就结束"：系统问一句、用户答一句，这个回答接不回原来的问题。
> - 会话编号、补话节点、摘要、记忆分层，**一个都没做**。
> - 面试口径："现在是单轮，如果要做我会这样设计。"

**怎么用**：先背第 0 节的问题树，再逐问看。每一问都按「他真正想问什么 → 一句话怎么答 → 继续追怎么展开 → 别说错」写。

## Q1：你们支持多轮吗？

**他真正想问的**：你分不分得清"单轮"和"多轮"，以及会不会吹。

**一句话怎么答**：

> 不支持，现在是单轮。用户问一句、系统答一句，就结束了。多轮的本质不是"存聊天记录"，是"把半句话补成整句话"。

**他继续追时怎么展开**：

先看三个日常场景，全都接不住：

```
你：华东的销售额是多少？
你：那华南呢？          ← 系统只看到"那华南呢"四个字

你：查一下近 7 天的订单量
你：换成近 30 天        ← 系统不知道"换成"是换什么

系统：时间范围选本月、上月还是最近 7 天？
你：最近 7 天           ← 系统只收到四个字，不知道前面问的是什么
```

共同点：**单独拿出来，都是半句话。**

所以多轮要解决的，就是"把半句话补完整，再交给后面的流程"。

**别说错**："我们支持多轮。"——一问"那华南呢"就穿帮。

---

## Q2：为什么"那华南呢"接不住？技术上卡在哪？

**他真正想问的**：你是真看过代码，还是只会讲概念。

**一句话怎么答**：

> 两个硬伤：一是每次查询都从零开始，二是澄清问完就结束，答不回去。

**他继续追时怎么展开**：

**硬伤一：每次查询都是新的一次。**

代码里一次查询开一个线程编号（`thread_id = query_id`），查完就结束。下一次问"那华南呢"，系统眼里是一个全新的、没头没尾的问题。

而且中间状态存在内存里，服务一重启全没了。不过这还不是关键——**就算不重启也没用，因为一个线程只服务一次查询，下一轮根本不会复用它。**

打个比方：你去银行办业务，每说一句话就换一个柜员，新柜员还不看之前的记录。你刚说"我要取钱"，下一句"取五百"，新柜员只会问"取什么？"

**硬伤二：澄清是死路。**

系统问完一句，这条流程就结束了。用户答"最近 7 天"，前端只能把这四个字当成新问题再发一次——系统收到"最近 7 天"，还是不知道要查什么。

> 就像医生问"哪里疼"，你说"左边"，然后换了个医生进来。新医生只听到"左边"。

**别说错**："因为没有加 memory 参数。"——不是参数问题，是数据模型就没拆开。

## Q3：那怎么改？先改什么？

**他真正想问的**：你有没有先后顺序，还是上来就堆功能。

**一句话怎么答**：

> 先拆编号：把"一次聊天"和"一次查询"分开。这是所有多轮能力的前提，不拆后面都做不了。

**他继续追时怎么展开**：

| 编号 | 是什么 | 活多久 | 用来干嘛 |
|---|---|---|---|
| 会话编号（`session_id`） | 一次聊天 | 可能几十轮 | 把同一段聊天串起来 |
| 查询编号（`query_id`） | 一次提问 | 一次请求 | 查日志、追问题、对反馈 |

用吃饭打比方：**会话是一顿饭，查询是点的一道菜。** 一顿饭可以点很多道菜，但结账算一顿。

拆开之后，同一段聊天里的每一轮，都能找到"上一轮说了什么"。

然后按顺序做四件事：

1. 拆编号；
2. 请"补话员"（改写节点）；
3. 澄清做成"一问一答"（带编号）；
4. 长对话做压缩。

**别说错**："先做个记忆库。"——编号没拆，记忆存了也找不到人。

## Q4：指代怎么补？为什么先规则后模型？

**他真正想问的**：你是不是什么事都让大模型做。

**一句话怎么答**：

> 请个"补话员"站在流程最前面：拿上一轮的话 + 这一轮半句，拼成完整一句。先规则后模型——高频句式就那几种，规则零成本、不会瞎编、好排查。

**他继续追时怎么展开**：

补话员的工作就一句话：

> **上一句 + 这半句 → 拼成一句完整的话。**

比如：

- 上一句"华东的销售额是多少" + 这半句"那华南呢" = "华南的销售额是多少"
- 上一句"近 7 天的订单量" + 这半句"换成近 30 天" = "近 30 天的订单量"

补完交给后面的人。后面的人（生成查询、检查、查库）**根本不知道刚才在聊天**，他们只看到一句完整的话。

**第一档：死规则。** 高频句式直接套：

- "那 X 呢" → 换掉上一轮里的地区/品牌
- "换成 X" → 换掉上一轮里的时间
- "再来一次 / 重新查" → 原样再跑一遍

**第二档：模型兜底。** 规则没盖住的，再让模型补。指令就一句：

> 把这句话补成一个能独立看懂的问题，不要加用户没说的条件，判断不了就原样返回。

为什么先规则？三个原因：不花钱、不会瞎编、出了问题能解释。而且日常说法翻来覆去就那几种，规则能盖住大部分。

**加分点**：这套设计的关键约束是——**后面的流程不感知多轮**。多轮的不确定性全挡在"补话"这一层，好改、好测、好排查。

**别说错**："每句话都让模型改写一遍。"——多一次调用、多一次幻觉机会，还慢。

## Q5：改写错了怎么办？

**他真正想问的**：你把模型当神来用，还是当会出错的组件。

**一句话怎么答**：

> 三条纪律：温度设 0、失败就用原话、改写前后留痕。

**他继续追时怎么展开**：

1. **模型要"笨"一点**：温度设 0，能用小模型就别用大的——这活不需要创造力。
2. **失败不能报错**：超时、模型挂了，就拿原话继续跑。宁可少补，不能查不了。
3. **前后要留痕**：记下"原话是什么、补成了什么、规则补的还是模型补的"。否则用户问"你为什么查成这个"，你答不上来。

第三点最容易被忽略，但它是可解释性的基础。

**别说错**："改写失败就重试三次。"——重试也失败呢？必须有降级路径。

---

## Q6：澄清问完，用户答了，怎么接回去？

**他真正想问的**：你知不知道"问"和"答"要能对上号。

**一句话怎么答**：

> 给每个澄清问题编号，用户回答时把编号带回来，系统把"原问题 + 答案"拼成一句完整的话，再走完整流程。

**他继续追时怎么展开**：

现在是系统问一句、用户答一句，两句话对不上。改成：

1. 系统问的时候带编号：`c1：时间范围选哪个？本月 / 上月 / 最近 7 天`
2. 用户答的时候带回编号：`c1 = 最近 7 天`
3. 系统拿到"原问题 + 编号对应的答案"，拼成完整一句再往下走。

例子：

```
原问题：查一下销量
系统问：销量是指支付订单量，还是发货数量？（编号 c1）
用户答：支付订单量
拼起来：查一下销量（支付口径）
```

**一条铁律**：拼完之后，还是要走完整的检查流程（生成、校验、权限），不能因为"用户已经确认过了"就跳步。

**别说错**："让用户把问题重新说一遍。"——那要澄清干嘛。

## Q7：一次被问好几个问题怎么办？

**他真正想问的**：你会不会一次弹十个框吓跑用户。

**一句话怎么答**：

> 能合并成一次表单的，就别拆成多轮。只有"第二问依赖第一问"时才必须多轮。

**他继续追时怎么展开**：

| 歧义形态 | 例子 | 该怎么做 |
|---|---|---|
| 并列、互不依赖 | 时间 + 口径 + 对比基准 | 一次问完，别拆成三轮 |
| 级联、有依赖 | 先选业务域，才知道有哪些指标 | 必须多轮 |
| 一次超过 3 个 | 时间、口径、维度、基准全缺 | 挑最影响结果的 1–2 个，其余默认 |

每多一轮，就多一次流失、一次超时、一次"用户乱点"。

**加分句**："多轮澄清不是刚需，回填才是刚需。回填解决的是'问了白问'，多轮解决的是'一次问不全'。"

**别说错**："所有歧义都做成多轮。"——用户会烦。

---

## Q8：聊到 20 轮，上下文爆了怎么办？

**他真正想问的**：你知不知道 token 是要花钱的。

**一句话怎么答**：

> 最近 3 轮留原话，更早的压成一句话摘要。

**他继续追时怎么展开**：

```
【会话摘要】用户在查华南销售额，时间从近 7 天改成近 30 天，要求按品牌分组。
【最近对话】第 18、19、20 轮的原话
【这一轮的问题】...
```

三个坑：

- **否定条件别丢**：用户说过"不要含退款"，摘要不能变成"查销售额"。
- **数字别丢**："近 7 天"不能压成"近期"。
- **别反复压**：摘要是"旧摘要 + 新增的旧轮次"，不是"把摘要再摘要一遍"，不然越压越走样。

**别说错**："把历史全塞进 prompt。"——二十轮就爆，还贵。

---

## Q9：记忆怎么设计？什么都记吗？

**他真正想问的**：你知不知道"什么都记"等于"什么都没记"。

**一句话怎么答**：

> 分四层放，而且**不是什么都记**——只记用户明确确认过的口径、和重复出现三次以上的偏好。

**他继续追时怎么展开**：

| 格子 | 放什么 | 例子 |
|---|---|---|
| 工作记忆 | 这次查询正在用的东西 | 当前生成的查询、置信度 |
| 情景记忆 | 发生过什么事 | "上周你问过华东销售额" |
| 语义记忆 | 你这个人的习惯 | "他总爱按品牌看" |
| 程序记忆 | 做事的方法 | "'流水'要当成 GMV" |

用办公室打比方：工作记忆是你桌上正在处理的文件，情景记忆是部门会议记录，语义记忆是同事对你的印象，程序记忆是公司操作手册。

但最重要的不是"记"，是"不记"：

| 值得记 | 不值得记 |
|---|---|
| 用户明确确认过的口径 | 每次查出来的具体数字 |
| 说过三次以上的偏好 | 一次性的临时条件 |
| 用户纠正过的错 | 闲聊、寒暄 |

**没有写入策略的记忆系统，三个月后一定变成噪声源。**

**别说错**："把所有对话都存下来。"——存了也不会用，反而把模型带偏。

---

## Q10：怎么忘？

**他真正想问的**：你有没有考虑记忆会过期、会冲突。

**一句话怎么答**：

> 三条规矩：太久没用的降权、新旧冲突的作废但不删、条目太多先淘汰最不常用的。

**他继续追时怎么展开**：

- **按时间**：30 天没碰，权重减半。
- **按冲突**：新说法和旧说法冲突，旧的标"已作废"，但**不删**，方便追溯。
- **按容量**：一个人记的条目太多，先淘汰最不常用的。

**别说错**："定期清空。"——清空会把"用户确认过的口径"也删掉。

---

## Q11：多轮怎么评测？

**他真正想问的**：你连单轮都评不好，多轮怎么评。

**一句话怎么答**：

> 四类题：指代、省略、澄清、干扰。看整段对话有没有完成任务，不只看单轮对不对。

**他继续追时怎么展开**：

| 类型 | 例子 | 判分 |
|---|---|---|
| 指代 | 第 1 轮"华东销售额"，第 2 轮"那华南呢" | 第 2 轮地区是华南，指标仍是销售额 |
| 省略 | 第 1 轮"近 7 天"，第 2 轮"换成 30 天" | 时间被替换，其他不变 |
| 澄清 | 触发澄清，选完选项继续 | 最终查询包含所选口径 |
| 干扰 | 问个无关问题再回来 | 不串上下文 |

指标看**会话级任务达成率**：整段对话有没有达成目标，比单轮正确率更重要。

**别说错**："多轮就看最后一轮对不对。"——最后一轮对，可能是运气。

---

## Q12：这些你们做了吗？

**他真正想问的**：你会不会把设计说成实现。

**一句话怎么答**：

> 没做。现在是单轮：一次查询一个线程、中间状态在内存、澄清问完就结束。多轮要的会话编号、补话节点、澄清回填、摘要、记忆分层，都还没有。

**他继续追时怎么展开**：

如果问"先做哪个"：

> 先拆编号 + 澄清回填。这两件不改主链路，但能立刻把"问了白问"这个硬伤补上。补话节点可以第二步做，因为它需要改图的入口；记忆分层最后做，因为它是优化，不是刚需。

**别说错**："我们在规划中。"——面试官要的是"你知道怎么做"，不是"你在规划"。

## 名词解释（大白话）

| 词 | 大白话 |
|---|---|
| 单轮 / 多轮 | 一问一答就结束 / 能接着上一句继续聊 |
| 会话编号 | 一次聊天的编号，把几十轮串起来 |
| 查询编号 | 一次提问的编号，查日志用 |
| 补话（改写） | 把半句话补成完整的话 |
| 澄清（clarification） | 系统发现你问得不清楚，先反问一句 |
| 回填 | 用户答完，把答案接回原问题 |
| 滚动摘要 | 旧对话压成一句话，新对话留原话 |
| 工作 / 情景 / 语义 / 程序记忆 | 手上正在办的 / 发生过的事 / 你的习惯 / 做事方法 |
| 降级 | 高级做法失败时退回简单做法，保证还能用 |
| 留痕 | 把"原话、补成什么、为什么"记下来 |

## 考前 1 分钟

- **一句话**：多轮不是记聊天记录，是把半句话补成整句话。
- **两个硬伤**：一次查询一个线程、澄清问完就结束。
- **四步**：拆编号 → 补话 → 澄清编号 → 压缩。
- **三条纪律**：温度 0、失败用原话、前后留痕。
- **四层记忆**：工作 / 情景 / 语义 / 程序。
- **一条铁律**：后面的流程永远只看到一句完整的话。
- **收尾**：多轮的不确定性，全挡在"补话"这一层。
