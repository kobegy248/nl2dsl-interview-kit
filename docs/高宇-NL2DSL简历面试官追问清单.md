# 高宇 NL2DSL 简历面试官追问清单

> 视角：如果我是面试官，看到这份简历后，会重点验证候选人是否真的理解 NL2DSL 架构、数据治理、RAG 检索、大数据加工、AI 辅助开发和传统后端稳定性经验。

## 一、开场与项目总览

### 高概率问题

1. 你先用 3 分钟介绍一下自己，重点讲讲最近这个 NL2DSL 项目。
2. 你这份简历定位是 AI Agent / NL2DSL / 大数据工程师，你自己觉得最核心的竞争力是什么？
3. 智能数据查询平台是公司项目还是个人开源项目？两者之间是什么关系？
4. 你在公司项目里负责哪些模块？开源项目里又是怎么复现或沉淀的？
5. 这个项目解决的真实业务问题是什么？用户是谁？使用场景是什么？
6. 你说“面向数据治理平台”，具体接入的是哪些治理资产？
7. 你做的是 NL2SQL 还是 NL2DSL？为什么简历里强调 DSL？
8. 这个项目目前做到什么程度？是 Demo、内部工具、生产系统，还是开源验证项目？

### 面试官想验证什么

- 你是否能讲清项目边界，不把开源项目、公司项目、个人实践混在一起。
- 你是否真的理解“数据治理平台”和“智能问数”的关系。
- 你是否能用业务语言解释项目价值，而不是只堆技术名词。

## 二、NL2DSL 架构设计

### 高概率问题

1. 为什么不直接让 LLM 生成 SQL，而要先生成 DSL？
2. DSL 里包含哪些核心字段？metrics、dimensions、filters 分别代表什么？
3. DSL 到 SQL 的转换链路是怎样的？
4. DSL 校验具体校验哪些内容？
5. LLM 生成了不存在的字段或指标怎么办？
6. 指标口径是由 LLM 决定，还是由系统注册表决定？
7. “销售额”这种业务指标如何映射到底层 SQL 表达式？
8. 如果用户问“华东近7天销售额最高的5个商品”，系统完整执行流程是什么？
9. 你提到 10+ 个 LangGraph 节点，能按顺序画一下流程吗？
10. LangGraph 在这里解决了什么问题？不用 LangGraph 可以吗？

### 深挖问题

1. Agent 层和 Graph 层为什么要分开？如果合在一起有什么问题？
2. 复杂查询拆解后，多个子查询之间如何并行、串行或聚合？
3. Graph 节点之间传递的 State 结构大概长什么样？
4. 节点失败后怎么处理？哪些失败可以重试，哪些必须终止？
5. correct_dsl 是怎么工作的？它怎么知道应该重新检索什么？
6. 如何避免 DSL 修正陷入死循环？
7. SQLAlchemy 和 sqlglot 分别解决什么问题？
8. sqlglot 方言转换在什么场景下有价值？

### 容易被问穿的点

- 只说“DSL 更安全”，但说不出 DSL Schema 和校验项。
- 只说“LangGraph 编排流程”，但说不出节点、状态、条件分支。
- 说“降低幻觉”，但说不清系统到底在哪些环节拦截幻觉。

## 十二、高压追问与防穿帮问题

> 这一章不是为了背标准答案，而是帮助你提前识别面试官最可能连续施压的点。回答时优先保证真实、可解释、边界清楚，不要为了显得项目更大而硬编生产规模、核心职责或无法证明的数据。

## 1. 项目真实性与边界

### 高频高压问题

1. 你简历里写的是公司项目，GitHub 上又有个人开源项目，这两个到底是什么关系？
2. 公司项目里哪些模块是你亲自做的，哪些只是你了解或参与讨论过？
3. 你说开源项目是抽象复现，那它复现的是架构思想、业务流程，还是具体代码？
4. 如果我让你现场讲公司项目和开源项目的差异，你能说出 5 个具体差异吗？
5. 你有没有把个人项目里的能力包装成公司项目成果？
6. 公司项目里真实上线到什么程度，是生产系统、内部工具、PoC，还是技术预研？
7. 如果不能展开公司内部细节，你怎么证明自己确实做过这些模块？

### 连环追问链

1. 你先用一句话区分公司项目和开源项目。
2. 公司项目里你负责的最核心模块是哪一个？请只说你亲手做的。
3. 这个模块的输入、输出、依赖分别是什么？
4. 开源项目里对应模块在哪个目录？和公司项目相比删掉或简化了什么？
5. 如果我看代码，只看哪 3 个文件就能验证你说的核心链路？
6. 哪些内容你因为保密不能讲？不能讲的部分你会怎么替代表达？

### 回答底线

- 不要说“公司项目和开源项目完全一样”。
- 不要把开源项目的完整能力直接说成公司生产能力。
- 可以主动说：公司项目是业务实践，开源项目是个人抽象、复现和沉淀，用来展示架构理解和工程能力。

## 2. Vibe Coding 掌握度

### 高频高压问题

2. 哪些代码是 AI 写的，哪些关键逻辑必须你自己判断？

4. AI 生成的代码你是怎么 Review 的？有没有具体 checklist？
5. 你能举一个 AI 写错、你发现并修正的例子吗？

### 连环追问链

### 回答底线

- 不要把 Vibe Coding 讲成“AI 帮我把项目做完”。
- 要强调你负责需求拆解、架构边界、关键 Review、测试验证和最终质量。
- 最好准备一个具体模块案例，比如 DSL Validator、权限注入、RAG rerank 或评测框架。

## 3. 性能指标可信度

### 高频高压问题

1. 你写 800ms 降到 80ms，这个 800ms 和 80ms 分别测的是什么环节？
2. 成本下降 90% 是怎么计算的？是 token 成本、模型调用成本，还是整体机器成本？
3. 准确率 90% 的测试集有多少条？覆盖哪些问题类型？
4. 你测的是平均耗时、P95、P99，还是单次样例？
5. 冷启动、缓存命中、向量库首次加载这些情况算进去了没有？
6. Reranker 替代 LLM 粗排后，准确率有没有下降？怎么证明没有明显下降？
7. 如果面试官让你拿出实验记录，你能提供什么粒度的数据？

### 连环追问链

1. 先定义一下“重排序耗时”的起止点。
2. 测试环境是什么，CPU/GPU、模型版本、候选集大小分别是多少？
3. 样本集怎么构造，有没有只挑简单问题？
4. 800ms 是 LLM rerank，80ms 是 BGE-Reranker，这两个是否在同样候选规模下对比？
5. 如果候选从 Top20 变成 Top100，耗时会怎么变化？
6. 这个指标能不能代表生产环境？哪些因素会让生产耗时变差？

### 回答底线

- 不要把本地评测或局部链路压测说成全量生产指标。
- 要说清楚统计口径：测试集、候选集规模、模型版本、缓存状态、平均值或 P95。
- 如果没有完整实验记录，就说“这是局部评测口径，不代表所有生产场景”。
