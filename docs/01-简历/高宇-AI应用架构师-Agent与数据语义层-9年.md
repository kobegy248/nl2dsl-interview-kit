### 南京中软国际有限公司 / 拓维云创软件公司（2022 年 1 月 - 至今）

#### 智能数据查询平台（NL2DSL / AI Agent）| 核心开发 / 技术负责人

**项目背景：**
面向数据治理平台建设自然语言语义查询层。传统 NL2SQL 在企业生产环境不可用：SQL 不可校验、权限不可控、指标口径不统一、审计无法追溯，过不了甲方的安全审查。系统以"结构化 DSL + 系统执行"为骨架，让业务人员用自然语言查数，同时保证全过程可治理、可审计、可回溯。

**开源地址：**
个人开源实现：https://github.com/kobegy248/nl2dsl-engine

**技术栈：**
Python、FastAPI、LangChain、LangGraph、Milvus Lite、SQLAlchemy、sqlglot、jieba、BGE-Reranker、MySQL

**核心职责与成果：**

- **主导架构决策**：把"LLM 直接生成 SQL"改为"LLM 只出结构化 DSL、系统负责校验与执行"，用 DSL 作为语义契约承接指标、维度、过滤、排序、分页与后处理。该决策让查询从"不可校验"变为可校验、可审计、可归因，是项目通过甲方安全审查、具备可交付性的前提。
- 基于 LangGraph 设计 **16 节点查询状态机**（含校验、权限 2 个子图），覆盖歧义检测、RAG 检索、DSL 生成/校验/修正、权限注入、SQL 构建、安全扫描、沙箱预检、执行与审计的全链路；每个节点输出结构化 trace，可按 query_id 定位到具体失败环节。
- 设计 **Agent 层 + Graph 层双层架构**：Agent 层负责意图识别（7 类，YAML 配置化，新增意图不改代码）与子查询并行调度（asyncio + 信号量限流 + 依赖串行 + 失败传播），Graph 层保证单查询从 DSL 到 SQL 的确定性链路；复杂问题拆解后子查询并行执行，缩短端到端耗时。
- 设计**语义层治理模型**：把"销售额 / 华东 / 近 7 天"映射为指标口径、字段映射与值域编码。关键设计是"指标只存 alias，物理表达式由注册表权威下发，模型猜测的字段会被忽略"——从**机制上**消除口径漂移，而不是靠 prompt 约束模型别乱写。
- 设计**四集合检索**（schema / metrics / terms / history）并按实体类型分治：短实体走 jieba 关键词 + 向量双通道（短名精确匹配比语义相似更可靠），长文本历史走整句语义；召回后叠本地 BGE Cross-Encoder 精排（top10 → top5），配合阈值过滤与空召回回退，让有限的上下文窗口只保留有效信息。
- 在 DSL 层实现**两级权限**：行级过滤注入（tenant_id + 用户数据域）+ 列级敏感字段检查，SQL 执行前再叠安全扫描与沙箱预检。权限在**模型视野之外**注入，提示词无法绕过；未登记用户按 fail-closed 拒绝而非放行。
- 建设 **4 类 12 维自动化评测 + 回归门禁**（数据集指纹校验 + 维度阈值 + 非零退出），把"改坏了上线"挡在发布前；50 例全量基线 **69.7%**，据此定位出多表 join 与术语歧义是两个主要瓶颈，作为下一阶段优化目标。
- 建设**节点级 trace 与审计台账**（DSL / SQL / 耗时 / 错误码 / 扫描行数），支持按 query_id 回放定位召回不足、校验失败、权限拒绝与执行异常；审计查询的租户过滤下沉到 SQL 层，跨租户记录返 404 而非 403，不泄露记录存在性。
