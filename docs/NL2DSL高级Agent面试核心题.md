# NL2DSL 高级 Agent 面试核心题

基于 `D:\demo\db-gpt\NL2DSL` 的当前源码。**先练前 12 题**，能讲清当前代码、失败路径和取舍，再练 13～20 题；其余模块按岗位补充。每题建议用 2 分钟主答、3 分钟接受追问。源码行为不等于公司上线事实或个人贡献。

**优先级：** 标有【高频必问】的 9 题，优先练到能脱稿回答；其余 1～12 题是高级岗位的重点深挖；13～20 题按面试官关注的模块准备。这里的“高频”是根据简历内容和该项目的核心链路做的备考判断，并非招聘方的题目统计。

**先认三个名字：** `AgentController` 是“问题分流器”，判断走简单查询还是复杂查询；复杂查询调度器负责拆问题、安排子查询、汇总和解释结果；`Graph` 是“单条查询执行流水线”，负责生成/校验 DSL、加权限、构建 SQL、检查并执行。它们都是项目里的 Python 代码组件，不是三个不同的大模型。

## 第一组：架构主线（必答，1～4）

### 1. 【高频必问】面试官问：“用户输入一个问题后，系统如何决定用哪条处理流程？”

**白话答案：** 请求先到 `/api/v1/query`。接口先从问题里找指标、维度和时间词，再调用 `AgentController.route`。规划器按 `configs/intents.yaml` 判断问题类型：**判为“比较”就走复杂查询调度器**；趋势、占比、排行等类型当前也走这条路径，不过走复杂路径不代表一定拆成多条查询，例如趋势配置只生成一条按时间分组的子查询。只有判为普通单次查询，而且同时识别出指标和维度，才直接进入对应领域的 Graph；若判为单次查询却缺少指标或维度，则转入探索路径。规划器初始化或执行失败时，用实体数量和时间词做兜底。这个分流发生在 API 层。

**追问：**

1. 你说按关键词判断，‘同比’和‘趋势’同时出现时谁优先？优先级在哪配置？
2. 指标找到了但维度没找到，为什么不走简单路径？会落到哪条路径？
3. 领域新加一个指标别名，实体抽取何时能识别？误判后怎样用测试证明修好了？
4. 为什么不把复杂编排与单查询执行都放进一个 Graph？分两层后又引入了什么状态传递问题？
5. ‘增长’命中趋势关键词，但用户其实只要一个分组汇总，你改哪条规则？怎样防止把真正的同比问题误判？

**自己练：** 用“查昨天各品牌销售额”“查销售额”“比较今年与去年销售额增长率”分别推导意图、抽取到的指标/维度以及最终路径。最终分流以 `AgentController.route` 的实际结果为准。

**源码：** `nl2dsl/api_factory.py:870`、`nl2dsl/agent/controller.py:51`、`nl2dsl/agent/planner.py:306`、`nl2dsl/agent/orchestrator.py:97`。

### 2. 【高频必问】面试官问：“为什么让模型先写 DSL，不直接写 SQL？”

**白话答案：** 模型擅长理解用户想查什么，但不能让它随意决定公司指标怎么算。这里让模型先写一张结构化“查询单”，也就是 DSL，写明数据源、指标、维度、过滤和排序。程序再检查这张单是否用了已注册的指标、用户是否有权限，最后按配置生成 SQL。例如“销售额”应按注册表里的表达式计算，不能由模型临时猜一个字段。

**追问：**

1. 既然指标由注册表决定，模型在 DSL 中填错了物理字段，SQLBuilder 究竟听谁的？
2. 查询单格式合法，但 JOIN 或时间范围错了，谁发现？
3. 新业务问题 DSL 表达不了，你扩 DSL 还是允许模型写自由 SQL？
4. 治理配置里的销售额表达式本身写错，DSL 校验和 SQL 扫描都通过时，发布前如何发现？

**源码：** `nl2dsl/dsl/models.py:72`、`nl2dsl/dsl/semantic_validator.py`、`nl2dsl/sql_engine/builder.py:42`。

### 3. 【高频必问】面试官问：“用户要比较今年和去年的销售额，系统怎样拆开并算出增长率？”

**白话答案：** 系统先识别这是比较问题，把它分成“查去年销售额”和“查今年销售额”两条子查询。没有依赖时可以并行执行，每条都走同一套 Graph 校验与查询流程。拿到两期结果后，聚合器计算差值和增长率；如果去年是 0，当前实现把增长率记成 `N/A`。如果缺了一期，不能向用户给出完整增长结论，应该明确标成部分结果。

**追问：**

1. 你说能并行，最大并行数在哪里控制？
2. 只有今年成功、去年失败时，当前复杂查询调度器返回什么状态？聚合器会生成什么？
3. 如果后一条子查询依赖前一条结果，上游失败或只是 warning 时会怎样？
4. 今年和去年两条结果顺序颠倒，增长率正负号会不会反？聚合器靠什么识别基期？

**源码：** `nl2dsl/agent/dispatcher.py:137`、`nl2dsl/agent/orchestrator.py:463`、`nl2dsl/agent/aggregator.py`。

### 4. 【高频必问】面试官问：“这个项目为什么用 LangGraph？普通 Python 函数不行吗？”

**白话答案：** 普通函数也能串起流程，但这个项目并非一路直走：DSL 错了要纠正后再校验，SQL 执行失败可能简化重试，沙箱判为高风险时要暂停等待审批。Graph 把这些“下一步去哪”写成可检查的条件边，把每步读写的信息放进统一 State。不过它也增加了子图状态合并和检查点维护成本，所以不是节点越多越好。

**追问：**

1. DSL 校验失败是哪条边回到纠正节点？最多几轮？
2. 你说复杂查询有分支，当前 `detect_complexity` 的 simple/complex 最后是否走不同节点？
3. State 中 trace 多次写入怎样合并？
4. 人工审批前暂停后服务重启，状态丢失是框架限制还是检查点存储选型问题？

**源码：** `nl2dsl/graph/builder.py:147`、`nl2dsl/graph/edges.py`、`nl2dsl/graph/state.py:57`。

## 第二组：正确性与失败处理（必答，5～8）

### 5. 【高频必问】面试官问：“SQL 执行成功了，为什么结果还可能是错的？”

**白话答案：** 数据库只保证 SQL 能执行，不保证它回答了用户的问题。比如“华东”没映射成库里的地区编码、销售额用了错误金额字段、JOIN 放大了订单行数，SQL 都可能正常返回，却给出错误数字。因此我会拿用户问题逐项核对指标口径、时间范围、过滤、分组、排序和结果，并用固定样例做回归。

**追问：**

1. 华东在哪个函数转成编码？
2. 你说 JOIN 会放大金额，如何用一个样例验证？
3. 按组 Top5 为什么不能直接在总 SQL 上加 `LIMIT 5`？
4. 订单与三条明细 JOIN 后金额变三倍，你会先聚合、改指标表达式还是改 JOIN？如何回归？

**源码：** `configs/metrics.yaml`、`nl2dsl/sql_engine/builder.py:181`、`:293`、`:403`、`:581`。

### 6. 【高频必问】面试官问：“模型写了一个不存在的指标，系统会怎样处理？”

**白话答案：** 系统不会拿这个指标直接查库。校验器会指出它不在注册表中，Graph 把错误原因交给纠正节点，再生成一份 DSL 后重新校验。代码把生成尝试和校验失败都设了上限，达到 3 轮就结束，避免一直循环。用户直接提交 DSL 的 `/query/execute` 没有生成记录时，校验失败也不会自动帮他改。

**追问：**

1. 纠正节点连续返回同一份错误 DSL，哪一个计数保证结束？
2. 为什么用户提交的 DSL 不自动纠正？
3. 校验子图结束时主图后面还有权限节点，错误状态如何保证不继续执行？
4. 校验失败后主图仍有下一条边，你怎样证明错误 DSL 不会被执行？写哪个测试？

**源码：** `nl2dsl/graph/subgraphs.py:71`、`nl2dsl/graph/edges.py:53`。

### 7. 面试官问：“SQL 执行失败后，系统会自动重试吗？会不会把问题改错？”

**白话答案：** 当前 Graph 在执行失败后可以把 DSL 简化，再重新生成 SQL，最多只做一次这样的尝试。这里最重要的不是“第二次跑通”，而是简化后是否还在回答原问题。如果把地区或时间条件删了，结果即使查出来也不能冒充原答案。权限或安全拒绝也不该靠改写查询绕过去。

**追问：**

1. 当前简化节点实际会删掉哪些内容？
2. 你如何比较重试前后 DSL 的业务语义？
3. 数据库暂时超时与字段不存在，是否都适合同一重试策略？
4. 第一次 SQL 超时但仍在数据库运行，第二次重试会不会放大负载？如何取消和限流？

**源码：** `nl2dsl/graph/edges.py:194`、`nl2dsl/graph/builder.py:273`。

### 8. 【高频必问】面试官问：“用户问销售额，检索却找来订单数，你怎么排查？”

**白话答案：** 我先检查正确的销售额指标是否还在配置和索引里。如果在，就看它有没有进入粗召回候选；没进是分词、Embedding 或索引问题。进了但排在后面，就看 Reranker；排在前面却生成错 DSL，就看给模型的上下文和校验。检索只负责提示可能的指标，最终仍要按注册表判断能不能查。

**追问：**

1. 你说先查配置和索引，删掉 YAML 指标后旧向量会自动删除吗？
2. 进程启动后新增术语，Retriever 的词库会自动更新吗？
3. TopK 从 5 提到 20，召回可能提高，为什么答案反而变差？

**源码：** `nl2dsl/rag/retriever.py:21`、`nl2dsl/rag/sync.py:205`、`nl2dsl/semantic/registry.py`。

### 11. 面试官问：“两个用户同时做复杂查询，子任务会不会串状态？”

**白话答案：** 代码允许独立子查询最多 3 个并行，但每个子任务的检查点 ID 只用了类似 `sub_sq-1` 的名字。两个用户的计划都可能有 `sq-1`，若共享同一个内存检查点，状态标识就可能碰撞。更稳妥的做法是把父请求 ID、业务域和子任务 ID 一起放进标识，并用两个并发请求测试结果与 trace 是否隔离。

**追问：**

## 第四组：面试官继续深挖时再练（13～20）

### 13. 面试官问：“一个复杂问题为什么可能被规划两次？会有什么后果？”

**白话答案：** `/query` 先按规则规划一次，用来决定是否进入复杂查询调度器；进入后，调度器又抽取实体并重新规划。外层抽取实体时传了注册表，内层没传；内层如果配置了模型客户端，规划器还会先尝试让模型出计划，而外层默认只走规则。多数规则路径可能给出相同结果，但两次调用没有共用同一份计划：例如外层规则判为“趋势”，内层模型判为“比较”，调度器会按内层计划拆任务，和外层分流依据不一致。修复思路是把已确认的计划和所用配置版本传给调度器；这是改进方案，当前代码尚未这样做。

**追问：**

1. 外层只按规则、内层可能调用模型，遇到不同意图时到底以哪次计划为准？
2. 传入计划后，复杂查询调度器还需不需要重新做实体抽取？
3. 怎样写测试证明没有重复规划？
4. 外层和内层实体抽取参数不同，注册表更新期间怎样让同一请求绑定版本？

**源码：** `nl2dsl/api_factory.py:904`、`nl2dsl/agent/orchestrator.py:237`。

### 14. 面试官问：“多个 Graph 节点都写 trace，怎样保证日志不丢、不重复？”

**白话答案：** 项目把 trace 和 DSL 尝试记录放进统一 State，用 reducer 合并。当前 reducer 会按整条字典是否相等去重，这能避免子图把父图原有 trace 带回来时重复一遍。但两次真实事件内容恰好相同，也可能被当成重复项。因此真正做审计应给事件加唯一 ID、节点和尝试序号，再按 ID 去重，而不是只比较整条内容。

**追问：**

1. 两个并行节点同时写 trace，顺序可靠吗？
2. 哪些字段要做 reducer，哪些字段只能由一个节点写？
3. 事件 ID 如何跨重试和恢复保持稳定？
4. 两条真实 trace 内容一样却被去重，如何用事件 ID 保证审计不丢？

**源码：** `nl2dsl/graph/state.py:13`。

### 15. 面试官问：“复杂查询三条子任务成功两条、失败一条，能不能返回结果？”

**白话答案：** 当前复杂查询调度器会把部分失败标成 `warning`，仍对已有结果做聚合；全部被阻断才返回 `error`。这适合某些可独立展示的查询，但比较、占比等计算依赖完整输入，缺一个分母或基准就不能把部分数字写成完整结论。我会按意图区分“可展示的部分结果”和“不可计算的最终指标”，并在响应中列明缺失的子任务。

**追问：**

1. 只拿到今年销售额，增长率字段当前会是什么？
2. 上游子任务返回 warning 时，依赖它的下游会不会跳过？
3. 评测里 warning 算成功吗？
4. 部分结果被标 warning，前端展示增长率前必须检查哪些字段完整？

**源码：** `nl2dsl/agent/orchestrator.py:463`、`nl2dsl/agent/aggregator.py:79`、`nl2dsl/agent/dispatcher.py`。

### 16. 面试官问：“语义优化规则很多，规则之间相互影响怎么办？”

**白话答案：** 这个工程的优化器按优先级跑规则。一条规则改过 DSL，后面的规则就看到修改后的版本；这让顺序变得重要。我的处理思路是先定义哪些规则只做检查、哪些能自动修改，给每次修改记录前后差异，并用回归样例验证组合效果。当前代码里规则抛异常会被记录为 `Warn` 后继续运行；若是必须生效的治理规则，不能简单按普通优化失败处理。

**追问：**

1. 同优先级两条规则同时想改同一个字段怎么办？
2. 一条权限规则抛异常后继续查库，风险是什么？
3. 如何检测两条规则来回改写？
4. 治理规则执行异常只记 Warn，继续查询会发生什么？哪些规则要失败即拒绝？

**源码：** `nl2dsl/optimizer/engine.py:34`、`:107`。

### 17. 面试官问：“流式查询前端看到的进度，真的是后台实时执行进度吗？”

**白话答案：** 要分两条路径看。简单查询通过 Graph 的 `astream` 把节点更新发给客户端；复杂查询由复杂查询调度器用回调把计划、子任务和聚合事件放进队列，再通过流式接口发出去。两种事件来源和格式不同，前端不能只凭一个进度条断言每个步骤都实时可见。我会统一事件协议，保证都带 query_id、阶段、状态与最终结果，并处理断连和错误审计。

**追问：**

1. 客户端断开时后台任务会停止吗？
2. 队列没有上限，慢客户端会怎样？
3. 用户重连后如何避免重复跑 SQL？
4. 客户端断线后后台任务仍在跑，谁取消它？取消和错误审计怎样区分？

**源码：** `nl2dsl/api_factory.py:1150`、`:1175`、`:1279`。

### 18. 面试官问：“SQL 已经过安全扫描和沙箱，能说它安全了吗？”

**白话答案：** 还不能。扫描器目前主要用正则拦危险关键字、注释、UNION 和多语句，覆盖的是一批明显危险模式；沙箱用 SQLite 的执行计划做粗略估计，并实际跑一个限制行数的预览。这些都不能证明 SQL 的业务语义正确，也不能当成所有数据库的真实资源预算。生产还需要数据库只读权限、执行超时、行数和资源限制，并针对数据库方言做更可靠的检查。

**追问：**

1. `EXPLAIN` 失败返回 -1 时是拒绝还是放行？
2. `LIMIT 10` 为什么仍可能很贵？
3. 配置表达式进了 SQLAlchemy 的 `text()`，信任边界在哪？
4. 沙箱预览有 LIMIT，但数据库仍先做大 JOIN，如何设置真正的执行预算？

**源码：** `nl2dsl/sql_engine/scanner.py`、`nl2dsl/query/sandbox.py`、`nl2dsl/sql_engine/builder.py:108`。

### 19. 面试官问：“业务把销售额口径改了，正在运行的查询会立刻用新口径吗？”

**白话答案：** 当前工程启动时加载 YAML 配置，RAG 同步按文件修改时间判断是否需要 upsert，Retriever 还会在初始化时建立关键词库。因此改文件不等于所有运行中的组件立刻一起切换；配置和检索索引也不是原子发布。要避免一次查询拿到两个版本，我会给语义注册表和索引同一个版本，先构建并评测新版本，再让新请求整体切换，旧请求完成后再清理。

**追问：**

1. 只删 YAML，不删向量，旧指标还能被召回吗？
2. 正在跑的请求该用旧版还是新版？
3. 新版本评测失败如何回滚？
4. 指标口径切换中一半请求用旧版、一半用新版，审计如何记录版本并支持回滚？

**源码：** `nl2dsl/engine.py:175`、`nl2dsl/rag/sync.py:205`、`nl2dsl/rag/retriever.py:21`。

### 20. 面试官说：“现场把未知用户默认放行改成默认拒绝，你怎么改？”

**白话答案：** 我会先确认当前 `RowLevelSecurity.inject` 未找到用户配置时直接返回原 DSL，这是改动点。然后约定“未知用户”与“有权限但无额外行过滤”的区别：前者拒绝，后者允许继续。改完补单元测试覆盖已配置用户、未知用户、租户条件、原有 OR 过滤；再跑 API/Graph 集成用例，确认错误能正确返回且不会执行 SQL。公开 Demo 若需要匿名访问，应给明确的 Demo 身份和最小权限配置，不通过默认放行实现。

**追问：**

1. 拒绝应该抛什么异常，HTTP 返回什么状态？
2. 已经生成的 SQL 会不会被执行？
3. 如果权限配置服务暂时不可用，你会放行还是拒绝？
4. 未知用户拒绝后，Graph 是否还能走到 SQL 执行节点？如何写端到端断言？

**源码：** `nl2dsl/permission/row_level.py`、`tests/unit/test_permission_row.py`、`nl2dsl/graph/subgraphs.py`。
