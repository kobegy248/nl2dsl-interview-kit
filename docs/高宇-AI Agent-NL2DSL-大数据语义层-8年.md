### 南京中软国际有限公司 / 拓维云创软件公司（2022年1月 - 至今）

#### 智能数据查询平台（NL2DSL / AI Agent）| 核心开发

**项目背景：**  
面向数据治理平台建设自然语言语义查询层，解决传统NL2SQL在企业生产环境中SQL不可校验、权限不可控、指标口径不统一、审计困难等问题。系统采用“自然语言 → Agent编排 → RAG召回治理上下文 → 结构化DSL → DSL校验/权限注入/语义解析 → SQL构建/安全扫描/执行”的分层架构，让业务人员用自然语言查数，同时保证查询过程可治理、可审计、可回溯。

**开源地址：**  
个人开源实现：https://github.com/kobegy248/nl2dsl-engine

**技术栈：**  
Python、FastAPI、LangChain、LangGraph、Milvus Lite、MySQL、SQLAlchemy、sqlglot、jieba、BGE-Reranker

**核心职责与成果：**

- 负责NL2DSL核心架构设计与实现，将“LLM直接生成SQL”改为“LLM生成结构化DSL，系统负责校验、治理和SQL构建”，用DSL作为语义契约承接指标、维度、过滤条件、排序、分页和后处理。
- 在个人开源实现中采用Vibe Coding方式推进开发，通过AI辅助完成方案拆解、代码生成、单元测试补齐、问题定位和文档沉淀，并结合人工Review和自动化测试保证核心链路质量。
- 基于LangGraph设计10+节点查询管道，覆盖歧义检测、查询改写、RAG检索、DSL生成、DSL校验、DSL修正、权限注入、语义解析、SQL构建、安全扫描、沙箱预检、SQL执行、结果验证和审计日志。
- 设计Agent层与Graph层双层架构：Agent层负责意图识别、复杂查询拆解、子查询调度、结果聚合和自然语言解释；Graph层负责单查询从DSL到SQL执行的稳定链路，提升复杂问数场景的可扩展性。
- 设计语义层治理模型，基于指标、维度、数据源、业务术语、权限策略等治理配置，将“销售额、华东、近7天”等业务表达映射为标准指标口径、字段映射和值域编码，降低LLM幻觉和指标口径不一致风险。
- 设计Milvus Lite + 关键词检索 + MySQL的混合检索与元数据管理方案，向量库负责Schema、指标、术语和历史样例召回，jieba关键词检索负责短文本精确召回，MySQL负责元数据、审计日志和查询链路记录。
- 实现DSL层权限控制与安全防线，在DSL阶段注入行级权限、检查列级权限和敏感字段，在SQL执行前增加SQL安全扫描和沙箱预检，避免越权访问、危险SQL和大范围扫描风险。
- 引入BGE-Reranker替代LLM粗排，将重排序延迟从约800ms降低到约80ms，推理成本降低约90%，整体准确率保持在约90%。
- 建设自动化评测体系，围绕Semantic、Planning、Execution、Governance四类指标评估DSL生成质量、SQL执行成功率、结果准确率、权限注入、脱敏和审计覆盖情况，并支持基线对比和回归门禁。
- 建设链路追踪与审计能力，记录每个查询节点的输入、输出、耗时、状态、生成DSL、最终SQL和错误信息，支持通过query_id快速定位召回不足、DSL校验失败、权限拒绝和SQL执行异常。

**技术栈：**  
Java、Spark SQL、MySQL、Redis、HDFS、Yarn、Linux

**核心职责与成果：**

- 为 NL2DSL 查询引擎提供语义层底座：用 Spark SQL 加工表、字段、指标、维度、术语、权限等元数据，生成元数据宽表并同步为治理配置和检索索引，直接支撑 Schema 召回、指标召回、术语召回、字段值召回、DSL 校验和权限注入。
- 参与企业数据资产加工链路建设，对业务库表、字段信息、字段注释、指标口径、枚举值、术语别名和数据分布进行抽取、清洗、聚合和结果落库。
