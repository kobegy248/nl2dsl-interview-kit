# AI 应用后端岗位冲刺学习计划

> 制定日期：2026-10-17。目标岗位：高级 AI 应用后端、智能问数/数据平台研发；基线：有多年 Java 后端经验，但 NL2DSL 的部分核心代码目前还不能独立讲清。按每周 10–12 小时设计，共 12 周。时间不够时顺延，不靠背答案跳关。

## 岗位目标与边界

近期 [AI 数据工程开发岗位](https://careers.tencent.com/jobdesc.html?postId=2097954502169767936)将 Python、SQL/指标口径、后端工程、Agent/RAG、权限、可观测性和真实落地放在同一岗位里。另一类 [高级 Agent/AI Coding 岗位](https://careers.tencent.com/jobdesc.html?postId=2108442094254338048)还要求工具调用、工作流、评测、代码审查与团队级交付经验。前者更贴合当前转型路径；后者可作为后续冲刺，不作为本轮起点。

**本轮不投入大量时间的方向：** 模型预训练、微调算法、论文复现、纯 Spark 内核和多智能体框架大全。这些不是目标岗位的第一道门槛。

## 需要掌握的八项能力

| 优先级 | 能力 | 面试时要做到什么 |
| --- | --- | --- |
| 必须 | Python 后端：类型、异常、异步、FastAPI、Pydantic、pytest | 不依赖 AI 看懂接口和数据模型，现场改一个小需求并跑通测试 |
| 必须 | SQL 与语义层：数据源、指标、维度、过滤、DSL 校验、SQLAlchemy | 从一个自然语言问题画出 DSL，解释指标口径与最终 SQL 的关系 |
| 必须 | LLM 应用：API 调用、Prompt、结构化输出、工具调用、超时与重试 | 能解释模型负责什么，系统必须确定性处理什么 |
| 必须 | RAG：Embedding、关键词/向量召回、Rerank、TopK、版本与失效 | 能定位“召回错指标”是索引、召回、精排还是注册表问题 |
| 必须 | LangGraph：State、节点、条件边、子图、重试、checkpoint | 不看答案画出项目真实执行路径与失败分支 |
| 必须 | 治理与安全：行列权限、SQL 扫描、沙箱、提示词注入边界 | 能指出开源版已实现的防线和当前未覆盖的风险 |
| 必须 | 评测与工程化：固定数据集、基线、trace、延迟/成本、回归 | 每次改动能展示测试与评测结果，数字有实验口径 |
| 冲高薪必须 | 上线能力：缓存、并发、限流、只读连接、监控、发布回滚 | 能讲一个真实后端故障，以及 AI 链路的降级方案 |

Java 后端是已有优势，持续复习并准备真实案例，不要为了学 AI 把它丢掉。Spark/元数据加工只在真实参与的范围内讲。

### 1. Python 后端与接口工程（第 1 周，必须）

- **学到什么：** 类型标注、`dataclass`/Pydantic 模型、异常传播、上下文管理器、依赖注入、同步与异步的区别；理解 `async` 不会自动让 CPU 密集任务变快。熟悉 FastAPI 的请求校验、响应模型、错误码、生命周期和配置管理。
- **在项目里练：** 顺着 `nl2dsl/api.py → api_factory.py → dsl/models.py` 跟一条请求，画出入参、校验、业务调用、错误响应。用 pytest 增加一个非法参数或超时场景的测试。
- **掌握标准：** 能解释 400/422/500 各自可能从哪里来，现场给接口增加一个字段并更新测试；不靠 AI 直接写出一个简单的 Pydantic 模型和 pytest 断言。

### 2. SQL、指标口径与语义层（第 2–3 周，必须）

- **学到什么：** `JOIN`、聚合、分组、窗口函数、CTE、分页；指标与维度的区别，过滤发生在聚合前还是聚合后，时间粒度和去重口径如何影响结果。理解“模型识别意图，语义层决定可信字段与表达式”。
- **在项目里练：** 对照 `configs/metrics.yaml`、`nl2dsl/semantic/registry.py`、`resolver.py`、`sql_engine/builder.py`，从 5 个自然语言问题手写 DSL 和预期 SQL。检查未知指标、非法维度、空过滤、排序字段和 limit 的处理。
- **掌握标准：** 给定一条业务问题，10 分钟内解释“问题 → DSL → 注册指标/维度 → SQL”；能说清生成 SQL 与数据库真实执行结果之间还需要哪些验证。SQLAlchemy 只学项目用到的表达式和参数绑定，不必先刷完整 ORM。

### 3. LLM 应用基础（第 4 周，必须）

- **学到什么：** 消息结构、Prompt 模板、上下文窗口、温度与输出稳定性、JSON/Schema 约束输出、工具调用的请求与结果回填；超时、重试、退避、并发上限、Token 用量和成本。重试要区分临时失败与业务性失败，避免重复执行有副作用的工具。
- **在项目里练：** 读 `nl2dsl/llm/client.py`、`prompts.py`、`dsl/generator.py`，列出模型生成、解析、校验、纠错的边界。分别构造未知指标、歧义问题和非法 JSON，记录系统实际表现；工具调用作为岗位通用知识另做小实验，不把未在项目落地的能力写成项目贡献。
- **掌握标准：** 能回答“为什么不能直接执行模型写出的 SQL？”并画出确定性校验链；能说明模型服务不可用时接口如何失败或降级，而不是只说“重试三次”。

### 4. RAG 与数据资产检索（第 5–6 周，必须）

- **学到什么：** 文档切分、Embedding、向量相似度、关键词召回、混合召回、TopK、Rerank；离线建索引与在线查询的分工，元数据更新后索引失效或版本不一致的问题。掌握召回率、排序质量与查询延迟之间的权衡。
- **在项目里练：** 跟踪 `nl2dsl/rag/sync.py → store.py → retriever.py → reranker.py`；用固定问题检查“正确指标是否进入候选集”和“进入候选集后是否排到前面”，分别记录错误案例。开源版的 YAML 配置要与公司内部治理 API 区分开。
- **掌握标准：** 面试官问“问销售额却召回了订单数”，能按数据源、索引、召回、精排、语义注册表逐层排查；能解释增加 TopK 为什么可能提高召回却增加延迟和噪声。

### 5. Agent / LangGraph 工作流（第 7–8 周，必须）

- **学到什么：** State 的读写与合并、节点输入输出、条件边、子图、循环退出条件；失败重试、人工介入、checkpoint/恢复和幂等性。把“流程被状态与规则约束”与“模型自主决定下一步”区分开。
- **在项目里练：** 根据 `nl2dsl/graph/state.py`、`builder.py`、`subgraphs.py`、`edges.py` 画出实际执行图，逐节点标出读写字段。确认 `human_review`、checkpoint 等功能哪些是真正接线、哪些只是预留或设计想法。
- **掌握标准：** 不看图讲出正常路径、一次 DSL 修正路径和一次权限拒绝路径；面试官改动一个节点的返回值时，能推断后续路由和测试应如何变化。

### 6. 数据治理、权限与安全（第 9 周，必须）

- **学到什么：** 用户身份、角色、数据源/行/列级授权，最小权限与拒绝默认；SQL 白名单或 AST 检查、参数化、只读连接、超时和结果行数限制。理解 Prompt 注入、工具越权、敏感数据泄露不能只靠 Prompt 文案防范。
- **在项目里练：** 读 `nl2dsl/permission/row_level.py`、`column_level.py`、`sql_engine/scanner.py`、`query/sandbox.py`，写授权、越权、未知用户测试矩阵。对每一道防线明确写“代码已实现 / 测试已覆盖 / 尚待验证”，不推断其生产安全等级。
- **掌握标准：** 能说明权限应在哪些阶段校验，以及为何检索到一个指标不等于允许查询其数据；指出至少两个具体风险与对应的代码级防护方案。

### 7. 评测与可观测性（第 10–11 周，必须）

- **学到什么：** 建立包含正常、歧义、越权、失败场景的固定测试集；区分 DSL 合法率、指标命中率、SQL 可执行率、答案正确率。记录版本、样本数、成功定义、失败样本；看 P50/P95 延迟、Token 成本、错误率与链路 trace。
- **在项目里练：** 读 `nl2dsl/evaluation/`、`tests/evaluation/dataset/`、`audit/logger.py`，对同一批样本跑一次基线和一次改动后回归；选 3 个失败样本做归因。先确认仓库现有评测口径，再决定是否补指标。
- **掌握标准：** 能拿着原始样本和运行记录解释一个数字的分母、环境、版本及误差；能回答“准确率提高 5% 为什么线上体验仍可能变差？”

### 8. 生产交付与已有 Java 优势（第 11–12 周，冲高薪必须）

- **学到什么：** 接口限流、缓存与失效、连接池、队列、超时预算、降级、灰度发布、回滚和成本控制；区分 LLM、向量库、治理服务和数据库各自的故障域。复用自己真实的 Java 高并发、服务治理和线上排障经验。
- **在项目里练：** 画 NL2DSL 依赖图，为“模型超时、检索失败、治理配置过期、SQL 慢查询”各写一套检测、隔离、降级和告警方案。方案可以是设计练习，但简历上不能当成已经上线的个人成果。
- **掌握标准：** 能完整复盘一个自己真实处理的线上问题，并解释如果同类问题发生在 AI 链路，会怎样定位、止损、验证恢复；回答时给出实际证据，不编造 QPS、提效百分比或线上用户量。

**优先级提醒：** 前 3 周先把 Python 接口、DSL/SQL 和语义层打牢；第 4–8 周再连起模型、检索和工作流；第 9–12 周补安全、评测和交付。不要同时学多个 Agent 框架，也不要把“看过代码”当成“独立开发过”。

## 每周固定节奏

- 2 小时：读官方文档或项目设计，写出自己的 5 句话总结。
- 5 小时：沿一条真实请求读代码，完成本周最小修改或实验。
- 2 小时：补测试并记录一个失败案例。
- 1–3 小时：脱离答案口述，录音复盘；不会的点回代码查。

**通关规则：** 能在不让 AI 代答的情况下，用 5 分钟讲清模块输入、输出、异常路径；能在 30 分钟内完成一个小改动并解释测试结果。AI 可以辅助查资料、生成初稿、审查代码，但最后的设计和验证要自己完成。

## 12 周路线

| 4 | LLM 生成与边界 | 读 `llm/client.py`、`llm/prompts.py`、`dsl/generator.py` | 设计“未知指标/歧义提问/模型输出不合法”三个失败案例，说明系统处理方式 |

| 6 | Rerank 与配置版本 | 读 `nl2dsl/rag/reranker.py`、`nl2dsl/engine.py`；做一次同候选集排序实验 | 记录候选数、模型、机器、计时范围、质量指标；讲清 YAML/索引不同步窗口 |

| 8 | 长任务与失败恢复 | 读 `graph/nodes.py`、`edges.py`；检查 `human_review` 与 checkpoint 接线 | 区分已实现占位节点与生产审批流程；准备超时、重试、幂等设计题 |
| 9 | 权限与 SQL 安全 | 读 `permission/row_level.py`、`column_level.py`、`sql_engine/scanner.py`、`query/sandbox.py` | 写出授权/越权/未知用户测试矩阵；指出至少两个现有边界并给改进方案 |
| 10 | 评测与回归 | 读 `evaluation/models.py`、`baseline.py`、`tests/evaluation/dataset/` | 固定一组样例，比较改动前后结果；能解释分母、评分维度、失败样本 |
| 11 | 稳定性与可观测性 | 读 `audit/logger.py`、`feedback/`、`quality/`；复盘一个自己的 Java 线上故障 | 画 trace/审计/告警关系；写出 LLM 超时、检索失败、数据库慢查询的降级策略 |
| 12 | 面试与作品说明 | 按本仓库追问清单做 3 次完整模拟面试；核对简历每条成果 | 3 分钟项目介绍、白板图、一份可展示的测试/评测记录、真实个人贡献表 |

## 三个关口

**第 4 周末：基础关。** 随机给一个自然语言问题，10 分钟内写出 DSL，解释指标口径从哪里来，指明 SQLBuilder 的输入与输出。做不到就重复第 2–4 周。

**第 8 周末：系统关。** 不看文档画 Graph 正常路径与两个失败分支，现场指出代码位置；能说明 RAG 错、DSL 错、权限拒绝分别如何处理。做不到就重复第 5–8 周。

**第 12 周末：求职关。** 面试官连续追问项目真实性、个人角色、性能数字时，能给出真实边界与证据；现场独立改一个小需求并跑测试。通过后再把“AI 应用后端”作为简历主标题大规模投递。

从第 6 周起小范围试投每周 3–5 个匹配岗位，记录 JD、笔试题、追问和不会的点，反向调整下周练习。试投简历只写已经能独立解释和验证的技能与贡献；暂时不以“AI 架构师”或“模型算法工程师”为目标。

## 本周就开始

1. 用自己的环境跑通仓库 README 中的启动流程和一个最小查询；记录环境、命令与报错。代码仓库位于 `D:\demo\db-gpt\NL2DSL`。
2. 只读 `nl2dsl/dsl/models.py`、`nl2dsl/semantic/registry.py`、`nl2dsl/sql_engine/builder.py`，回答：“销售额为什么最终用注册表达式，而不是模型猜的字段？”
3. 跑 `tests/unit/test_sql_builder.py`，挑一个测试逐行解释输入、预期 SQL 和失败条件。
4. 在[面试复盘文档](2026-10-13-NL2DSL面试训练复盘与SQLBuilder专项.md)的五格问题中填真实经历；不清楚的标“待核实”，不要编。

**本周验收：** 发出一段 90 秒口述，讲明 `自然语言 → DSL → 指标校验/解析 → SQLBuilder → 扫描/执行`。能讲清这条最短链路，再进入下一周。
