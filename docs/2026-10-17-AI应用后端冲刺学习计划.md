# AI 应用后端从零到能面试：16 周学习计划

> 制定日期：2026-10-17；按 2026-10-18 重新排序。目标岗位：AI 应用后端、智能问数/数据平台研发，逐步冲击高级岗位。你有多年 Java 后端经验，不是编程小白；这里按“Python、LLM 和 Agent 从零学”设计。每周约 10–12 小时；没过关就顺延，不用赶进度。

## 先看这里：怎么学才会

这份文档按顺序读：**先看 16 周路线 → 做当前周的练习 → 用后面的能力详解补知识 → 最后用高频追问自测。** 不需要第一天就理解所有术语。第一轮只求能运行、能解释、能修改；第二轮才追求架构深度和面试表达。

- **每周只抓一个主问题。** 先用自己的话写“它解决什么问题”，再看代码；不懂的英文词先查输入、输出和例子。
- **用四步学每个模块：** 看一个正常例子 → 自己运行 → 故意制造一个错误 → 解释系统为什么这样处理。只看教程或背答案不算掌握。
- **学习记录只写四栏：** 我输入了什么、代码经过哪里、输出/报错是什么、我为什么相信这个解释。AI 可以提示，但最后一栏必须自己核对。
- **每周通关标准：** 不看稿讲 3 分钟；能改一个小需求并跑测试；能指出一个失败边界。未通过就重复该周，不直接跳到下个框架。

**先认识 8 个词：** API 是程序入口；SQL 是数据库查询语句；指标是“销售额”这样的计算口径；DSL 是受限制的结构化查询请求；LLM 是生成文本/结构的模型；RAG 是先找资料再生成；Agent 是模型在受控流程中选择并调用工具；MCP 是连接工具/资源的协议。现在只需知道用途，细节在对应周学习。

## 16 周路线：照这个顺序走

| 阶段 | 周 | 这周只学什么 | 亲手做的最小任务 | 过关时能回答 |
| --- | --- | --- | --- | --- |
| 打地基 | 1 | Python 基础：函数、字典、类型、异常、pytest | 运行 `tests/unit/test_exceptions.py`，故意改错一个预期并看测试失败 | “这段测试给了什么输入，为什么通过/失败？” |
| 打地基 | 2 | HTTP/FastAPI/Pydantic：请求到响应 | 跟踪 `nl2dsl/api.py` 的一个接口，加一个非法参数测试 | “请求在哪里校验，错误怎样返回？” |
| 打地基 | 3 | SQL：`SELECT`、过滤、聚合、分组、JOIN | 在模拟数据上手写 5 条查询并检查结果 | “销售额按地区汇总为什么要分组？” |
| 智能问数 | 4 | 指标、维度、DSL 与注册口径 | 对照 `configs/metrics.yaml` 手写 5 个问题的 DSL | “模型猜的字段与注册口径冲突时听谁的？” |
| 智能问数 | 5 | SQLBuilder 与确定性校验 | 从 DSL 推导 SQL，补一个未知指标/非法维度测试 | “为什么不直接执行模型写的 SQL？” |
| 模型接入 | 6 | LLM 调用与结构化输出 | 让一个问题产生 DSL；构造非法 JSON 和超时 | “模型输出不合法怎么办？” |

| 检索 | 8 | Rerank、TopK 与索引更新 | 对同一批问题比较候选顺序与耗时 | “召回错了是索引、召回还是排序？” |
| 工作流 | 9 | Graph 的 State、节点、边 | 画出一个请求的真实正常路径 | “每个节点读写什么？” |
| 工作流 | 10 | 失败分支、重试、退出条件 | 画 DSL 错误和权限拒绝两条路径 | “失败后去哪，何时停止？” |
| 安全 | 11 | 行列权限、SQL 安全、提示词注入 | 做授权/越权/未知用户测试矩阵 | “检索到指标就能查询数据吗？” |
| 交付 | 12 | 评测、延迟、成本、真实贡献 | 跑固定样本；整理一个真实 Java 故障和 NL2DSL 代码证据 | “准确率的分母是什么？你具体做了什么？” |
| 独立 Agent | 13 | 函数工具与 MCP | 做查工单、查知识库等工具，至少一个通过 MCP 接入 | “工具参数错或越权时谁来拦？” |
| 独立 Agent | 14 | 上下文、会话与长期记忆 | 连续多轮处理同一工单，模拟历史过长与过期信息 | “怎样记住任务又不乱记敏感信息？” |
| 独立 Agent | 15 | 人工审批、持久化、恢复 | 关闭工单前暂停；重启后恢复；重复提交不重复关闭 | “审批期间进程重启怎么办？” |
| 独立 Agent | 16 | Agent 测试、Trace、成本；多 Agent 判断 | 跑至少 20 条固定样本，展示 3 个失败案例 | “为什么现在用单 Agent，何时才用多 Agent？” |

**四个关口：** 第 3 周能独立写基础 Python/SQL；第 6 周能讲清 `问题 → DSL → SQL` 和模型失败处理；第 12 周能用代码、测试与真实经历讲清 NL2DSL；第 16 周能演示独立 Agent 的审批、恢复和测试。任何关口不过就补相应周，不用背面试答案掩盖缺口。

**投递节奏：** 第 6 周起可以小范围试投匹配岗位，收集真实面试反馈；第 12 周关口通过后扩大投递。第 13–16 周是增强竞争力，不是必须等完才能找工作。简历只写已经亲手完成且能解释的贡献。

## 第 1 周今天就做

1. 打开 NL2DSL 仓库 `D:\demo\db-gpt\NL2DSL` 的 README，记录 Python 环境、启动命令和第一次报错；先把环境跑通。
2. 在仓库根目录尝试运行 `python -m pytest tests/unit/test_exceptions.py -q`。若提示缺少 Python 或依赖，按 README 配环境并记录错误，不要跳过。
3. 暂时把一个 `assert` 的预期状态码改错，再运行并记录失败提示；然后恢复原值重跑。不要先改产品代码。
4. 用自己的话写 4 句话：“测试给了什么输入、调用了谁、预期什么、改坏后为什么失败。”发给我或放进学习记录，我们按你的答案继续讲下一小步。

**第 1 周达标：** 能自己运行测试并解释一个断言。暂时不要求你讲清 RAG、LangGraph 或 MCP。

**第一课示范：** `tests/unit/test_exceptions.py` 中有这样的代码：

```python
exc = ValidationError("invalid field")
assert exc.status_code == 400
```

`ValidationError(...)` 创建一个“输入不合法”的错误对象；`exc` 是保存它的变量；`exc.status_code` 取出这个对象里的状态码；`assert` 要求左边的真实值等于右边的预期值 `400`。如果你把预期改成 `403`，测试应失败；恢复成 `400` 后再运行。**请自己回答：`400` 是谁设定的？** 沿着 `nl2dsl/exceptions.py` 找到定义，找到后再算这课结束。

Java 后端是已有优势，持续复习并准备真实案例，不要为了学 AI 把它丢掉。Spark/元数据加工只在真实参与的范围内讲。

### 1. Python 后端与接口工程（第 1–2 周，必须）

- **学到什么：** 类型标注、`dataclass`/Pydantic 模型、异常传播、上下文管理器、依赖注入、同步与异步的区别；理解 `async` 不会自动让 CPU 密集任务变快。熟悉 FastAPI 的请求校验、响应模型、错误码、生命周期和配置管理。
- **在项目里练：** 顺着 `nl2dsl/api.py → api_factory.py → dsl/models.py` 跟一条请求，画出入参、校验、业务调用、错误响应。用 pytest 增加一个非法参数或超时场景的测试。
- **掌握标准：** 能解释 400/422/500 各自可能从哪里来，现场给接口增加一个字段并更新测试；不靠 AI 直接写出一个简单的 Pydantic 模型和 pytest 断言。

### 2. SQL、指标口径与语义层（第 3–5 周，必须）

- **学到什么：** `JOIN`、聚合、分组、窗口函数、CTE、分页；指标与维度的区别，过滤发生在聚合前还是聚合后，时间粒度和去重口径如何影响结果。理解“模型识别意图，语义层决定可信字段与表达式”。
- **在项目里练：** 对照 `configs/metrics.yaml`、`nl2dsl/semantic/registry.py`、`resolver.py`、`sql_engine/builder.py`，从 5 个自然语言问题手写 DSL 和预期 SQL。检查未知指标、非法维度、空过滤、排序字段和 limit 的处理。
- **掌握标准：** 给定一条业务问题，10 分钟内解释“问题 → DSL → 注册指标/维度 → SQL”；能说清生成 SQL 与数据库真实执行结果之间还需要哪些验证。SQLAlchemy 只学项目用到的表达式和参数绑定，不必先刷完整 ORM。

### 3. LLM 应用基础（第 6 周，必须）

- **学到什么：** 消息结构、Prompt 模板、上下文窗口、温度与输出稳定性、JSON/Schema 约束输出、工具调用的请求与结果回填；超时、重试、退避、并发上限、Token 用量和成本。重试要区分临时失败与业务性失败，避免重复执行有副作用的工具。
- **在项目里练：** 读 `nl2dsl/llm/client.py`、`prompts.py`、`dsl/generator.py`，列出模型生成、解析、校验、纠错的边界。分别构造未知指标、歧义问题和非法 JSON，记录系统实际表现；工具调用作为岗位通用知识另做小实验，不把未在项目落地的能力写成项目贡献。
- **掌握标准：** 能回答“为什么不能直接执行模型写出的 SQL？”并画出确定性校验链；能说明模型服务不可用时接口如何失败或降级，而不是只说“重试三次”。

### 4. RAG 与数据资产检索（第 7–8 周，必须）

- **学到什么：** 文档切分、Embedding、向量相似度、关键词召回、混合召回、TopK、Rerank；离线建索引与在线查询的分工，元数据更新后索引失效或版本不一致的问题。掌握召回率、排序质量与查询延迟之间的权衡。
- **在项目里练：** 跟踪 `nl2dsl/rag/sync.py → store.py → retriever.py → reranker.py`；用固定问题检查“正确指标是否进入候选集”和“进入候选集后是否排到前面”，分别记录错误案例。开源版的 YAML 配置要与公司内部治理 API 区分开。
- **掌握标准：** 面试官问“问销售额却召回了订单数”，能按数据源、索引、召回、精排、语义注册表逐层排查；能解释增加 TopK 为什么可能提高召回却增加延迟和噪声。

### 5. Agent / LangGraph 工作流（第 9–10 周，必须）

- **学到什么：** State 的读写与合并、节点输入输出、条件边、子图、循环退出条件；失败重试、人工介入、checkpoint/恢复和幂等性。把“流程被状态与规则约束”与“模型自主决定下一步”区分开。
- **在项目里练：** 根据 `nl2dsl/graph/state.py`、`builder.py`、`subgraphs.py`、`edges.py` 画出实际执行图，逐节点标出读写字段。确认 `human_review`、checkpoint 等功能哪些是真正接线、哪些只是预留或设计想法。
- **掌握标准：** 不看图讲出正常路径、一次 DSL 修正路径和一次权限拒绝路径；面试官改动一个节点的返回值时，能推断后续路由和测试应如何变化。

### 6. 数据治理、权限与安全（第 11 周，必须）

- **学到什么：** 用户身份、角色、数据源/行/列级授权，最小权限与拒绝默认；SQL 白名单或 AST 检查、参数化、只读连接、超时和结果行数限制。理解 Prompt 注入、工具越权、敏感数据泄露不能只靠 Prompt 文案防范。
- **在项目里练：** 读 `nl2dsl/permission/row_level.py`、`column_level.py`、`sql_engine/scanner.py`、`query/sandbox.py`，写授权、越权、未知用户测试矩阵。对每一道防线明确写“代码已实现 / 测试已覆盖 / 尚待验证”，不推断其生产安全等级。
- **掌握标准：** 能说明权限应在哪些阶段校验，以及为何检索到一个指标不等于允许查询其数据；指出至少两个具体风险与对应的代码级防护方案。

### 7. 评测与可观测性（第 12 周，必须）

- **学到什么：** 建立包含正常、歧义、越权、失败场景的固定测试集；区分 DSL 合法率、指标命中率、SQL 可执行率、答案正确率。记录版本、样本数、成功定义、失败样本；看 P50/P95 延迟、Token 成本、错误率与链路 trace。
- **在项目里练：** 读 `nl2dsl/evaluation/`、`tests/evaluation/dataset/`、`audit/logger.py`，对同一批样本跑一次基线和一次改动后回归；选 3 个失败样本做归因。先确认仓库现有评测口径，再决定是否补指标。
- **掌握标准：** 能拿着原始样本和运行记录解释一个数字的分母、环境、版本及误差；能回答“准确率提高 5% 为什么线上体验仍可能变差？”

### 8. 生产交付与已有 Java 优势（第 12 周起持续练，冲高薪必须）

- **学到什么：** 接口限流、缓存与失效、连接池、队列、超时预算、降级、灰度发布、回滚和成本控制；区分 LLM、向量库、治理服务和数据库各自的故障域。复用自己真实的 Java 高并发、服务治理和线上排障经验。
- **在项目里练：** 画 NL2DSL 依赖图，为“模型超时、检索失败、治理配置过期、SQL 慢查询”各写一套检测、隔离、降级和告警方案。方案可以是设计练习，但简历上不能当成已经上线的个人成果。
- **掌握标准：** 能完整复盘一个自己真实处理的线上问题，并解释如果同类问题发生在 AI 链路，会怎样定位、止损、验证恢复；回答时给出实际证据，不编造 QPS、提效百分比或线上用户量。

**优先级提醒：** 第 1–3 周学 Python、接口与 SQL；第 4–6 周理解 DSL、SQLBuilder 与模型；第 7–10 周才学检索和工作流；第 11–12 周练安全、评测与交付；第 13–16 周做独立 Agent。不要同时学多个 Agent 框架，也不要把“看过代码”当成“独立开发过”。

## 面试复习手册：学完对应周再看

下面的“高频”是针对高级 AI 应用后端/智能问数岗位，结合 [AI 数据工程岗位](https://careers.tencent.com/jobdesc.html?postId=2097954502169767936)、[DataAgent 岗位](https://careers.tencent.com/jobdesc.html?postId=2090281754874265600)和[高级 Agent 岗位](https://careers.tencent.com/jobdesc.html?postId=2108442094254338048)要求作出的备考排序，**不是面试题出现概率的统计结果**。这是复习用题库，不是第一周必背清单；学完对应周再答。先掌握 S 级，再补 A 级；B 级只需达到能解释适用场景。

| 级别 | 重点 | 你至少要会什么 | 暂时不用钻到哪里 |
| --- | --- | --- | --- |
| S | 项目真实性与个人贡献 | 讲清背景、真实需求、你亲手改过的文件/测试、遇到的失败及证据；严格区分公司版与开源版 | 不编生产数字和没做过的模块 |

| S | 指标语义层与 SQL 正确性 | 手写 DSL，说明注册指标、维度、过滤、权限如何影响 SQL；解释口径冲突和歧义 | 不用先研究所有数据库方言 |
| S | RAG 检索与质量排查 | 分清索引、召回、精排、注册表四层；拿具体错例定位问题 | 不用手推向量模型数学细节 |
| S | Agent/Workflow 与失败恢复 | 能画 State、节点、条件边和重试/退出条件；区分已实现与设计方案 | 不用同时学多个 Agent 框架 |
| S | 权限、安全、评测 | 越权不能靠 Prompt 防；有固定数据集、失败样本和可复现指标 | 不用先搭完整商业监控平台 |
| A | Python/FastAPI 工程能力 | 独立改接口、写测试、解释异常/异步/超时 | 不用背冷门语法题 |
| A | LLM 接入与结构化输出 | 会处理非法输出、模型超时、工具副作用和成本 | 不用训练或微调模型 |
| A | 生产稳定性与 Java 后端优势 | 用自己真实故障讲限流、缓存、降级、监控、回滚 | 不编 AI 项目线上规模 |
| B | MCP、模型选型、Prompt 注入细节 | 理解协议/工具边界、成本与风险，能做一个小实验 | 不用追逐每个新框架/模型 |

### 高频追问 1：这项目真的落地了吗？你到底做了什么？【S】

- **要准备的事实：** 项目为什么要做、服务谁、数据从哪里来、如何验收、你修改过的模块、具体提交/测试证据。公司内部版本通过治理 API 取元数据，开源版用 YAML 和模拟数据；这两者不能混成一个架构描述。
- **回答顺序：** 真实背景 → 你负责的范围 → 一次具体改动 → 验收方式 → 仍有的限制。说“我写了构建模块和测试验收”时，要能指向具体文件、测试和改动记录；如果目前无法确认代码归属，先说“参与/维护/验证”，核实后再定措辞。
- **练习/过关：** 找出 1 个自己确实完成的改动，写出修改前问题、方案、失败尝试、测试结果。面试官连续追问 5 分钟仍能自洽；不知道的数据直接说不掌握，并解释如何核实。

### 高频追问 2：用户问“上月各地区销售额”，系统怎样一步步得到结果？【S】

- **必须讲到：** API 收请求 → 检索候选指标/维度 → 模型生成结构化 DSL → DSL/语义校验 → 注册口径解析 → SQL 构建与扫描 → 权限检查/安全执行 → 结果返回、审计或反馈。**这只是学习用检查清单，回答时必须按仓库实际调用顺序修正，不能把清单当作已实现事实。**
- **追问准备：** 召回不到指标怎么办？DSL 字段不合法怎么办？SQL 能生成但数据库报错怎么办？某个阶段超时会不会继续执行？每个问题按“输入、失败信号、处理分支、用户看到什么”回答。
- **练习/过关：** 从 `nl2dsl/api.py` 出发跟一个请求，画 1 张真实调用图；用 3 分钟不看稿讲完，再现场指出至少 5 个对应代码位置。

### 高频追问 3：为什么不能让大模型直接生成 SQL？SQLBuilder 的价值是什么？【S】

- **必须讲到：** 模型输出有歧义、可能幻觉字段、忽略指标口径或生成越权/危险语句；DSL 是受限中间表示，注册表提供可信口径，Builder 把经校验的 DSL 转为 SQL。SQL 正确还要考虑 JOIN、时间粒度、聚合前后过滤、参数绑定和方言。
- **追问准备：** 模型说 `sales_amount`、注册指标却是 `SUM(paid_amount)` 时听谁的？同一个“用户数”有 `COUNT(*)` 与 `COUNT(DISTINCT user_id)` 怎么处理？不能只说“用 Prompt 约束”，要说具体校验和拒绝路径。
- **练习/过关：** 手写 5 条 DSL 和预期 SQL，至少覆盖未知指标、非法维度、错误时间范围、无权限字段、分页边界；用 `tests/unit/test_sql_builder.py` 或相邻测试验证预期。

### 高频追问 4：RAG 召回错了怎么定位？为什么还要 Rerank？【S】

- **必须讲到：** 先确认 YAML/API 元数据及索引版本，再看正确候选是否进入 TopK；没进入是写入/检索问题，进了但排后是排序问题，排第一却生成错 DSL 是生成/解析问题。Rerank 是对候选重排，不能凭空补回完全没召回的指标。
- **追问准备：** 关键词召回与向量召回各擅长什么？TopK 调大有何代价？指标更新后怎样避免旧向量与新口径混用？
- **练习/过关：** 固定 10 个问题，记录候选 TopK、正确指标位置、最终 DSL 和耗时；挑 2 个错误样本写出可验证的归因，而非只说“换更好的模型”。

### 高频追问 5：为什么用 LangGraph？节点失败或重复执行怎么办？【S】

- **必须讲到：** State 保存哪些数据、节点读写什么、条件边依据什么路由、修正循环何时终止。框架解决流程组织，不自动保证业务正确或生产持久化；checkpoint、人工审批、幂等要以实际接线为准。
- **追问准备：** LLM 节点超时能否重试？数据库查询是否可重复执行？如果工具有写入副作用，重试如何避免重复写？人工审核节点是真功能还是占位？
- **练习/过关：** 对照 `nl2dsl/graph/` 画正常、校验失败、权限拒绝 3 条路径；给出一个节点错误的复现输入、期望路由和断言。

### 高频追问 6：如何防止越权、SQL 注入和 Prompt 注入？【S】

- **必须讲到：** 身份与权限在服务端验证，行/列权限不能依赖模型自觉；结构化 DSL、字段白名单/AST 扫描、参数绑定、只读账号、超时与结果上限是不同层的防线。检索结果和用户输入都是不可信内容，不能获得系统指令或工具授权。
- **追问准备：** 用户能检索到“工资指标”的说明，是否就能查工资数据？如果 LLM 在工具参数里填了未授权字段，哪一层拦？若 SQL 扫描器漏判，数据库账号还能挡什么？
- **练习/过关：** 写 6 个用例：合法查询、无权指标、无权列、未知用户、危险 SQL、注入式提问；标明仓库已有测试、需要补的测试、生产还需加的防线。

### 高频追问 7：你说准确率提升，怎么证明？【S】

- **必须讲到：** 固定测试集和版本，写清样本来源、分母、成功判定与评估粒度；分开统计检索命中、DSL 有效、SQL 可执行、答案正确，以及延迟和成本。不能把 10 个演示案例的通过率包装成线上准确率。
- **追问准备：** 指标 Top1 命中提高但答案正确率下降可能是什么原因？同一问题每次模型输出不同怎么复测？测试集泄漏、样本偏差怎么识别？
- **练习/过关：** 用仓库评测数据跑一次基线，记录命令、配置、样本数和失败清单；改一个参数后重跑，能逐样本说明差异。没有真实提升就展示排查过程，不编百分比。

### 高频追问 8：模型慢、贵、不稳定，怎样上线？【A】

- **必须讲到：** 拆分端到端耗时：检索、Rerank、模型、SQL；分别设超时预算、并发上限和错误处理。缓存要考虑权限与元数据版本，重试要考虑幂等，降级要明确用户是否得到部分结果、友好失败还是稍后重试。
- **追问准备：** P95 很慢但平均值正常怎么查？模型 429/超时怎么办？治理服务更新期间缓存如何失效？如何限制一次查询扫描大量数据？
- **练习/过关：** 画一张调用链耗时表，针对 3 个故障写出“检测 → 止损 → 恢复 → 验证”；区分你做过的 Java 生产实践与在 NL2DSL 上提出的设计。

### 高频追问 9：你说会 vibe coding，如何保证代码不是“AI 写了但你不懂”？【A】

- **必须讲到：** 自己定义需求和验收条件，AI 辅助读代码/生成候选实现；自己审查权限、边界、依赖和测试，亲自运行、复现、修正。讲一个 AI 初稿出错而你定位并改正的真实例子。
- **追问准备：** AI 生成的测试是否只验证自己写的假设？依赖升级或许可证怎么审？线上问题发生时不用 AI 是否能定位？
- **练习/过关：** 现场不依赖 AI 解释自己展示的每段核心代码；准备一份“需求 → Prompt/建议 → 人工改动 → 测试证据”的真实记录。

### 高频追问 10：你做过哪些真实的后端设计和线上排障？【A】

- **必须讲到：** 从过去 Java 项目选 2 个确实参与的案例，分别覆盖一次系统设计和一次故障处理。每个案例按约束、个人决策、权衡、上线验证、结果与不足来讲。
- **追问准备：** 为什么选缓存/消息队列/索引？一致性如何保证？流量突增怎么限流？指标或日志如何证明确实解决？
- **练习/过关：** 每个案例能讲 5 分钟，经得起 3 轮细节追问；没有测量过的收益明确说“未量化”。用这些经历证明你能把 AI 功能做成可靠服务，而不只是会调模型 API。

**第 12 周扩大投递前的自测线：** 能独立讲清追问 1–3；拿得出追问 4–7 中至少各一个可复现样本或测试；追问 8–10 用真实经历与设计边界作答。未达到时仍可试投后端+AI 应用结合岗收集反馈，但不把高级 Agent 架构岗当第一批目标。

## 第 13–16 周详解：独立做通用 Agent

NL2DSL 是智能问数工作流的主线；下面补的是**通用 Agent 应用岗常见、但不能直接算作 NL2DSL 项目贡献**的能力。每周仍按 10–12 小时安排。第 6 周起的小范围试投和第 12 周后的正式投递照常进行，不必等补充计划全部完成才找工作。

**练习载体：独立做一个“工单处理 Agent”。** 用模拟工单和知识库数据，提供“查工单、查处理规范、生成处理建议、关闭工单”四类能力。前三类可自动执行；关闭工单必须经服务端权限校验和人工确认。这个小项目只用于学习与作品展示，不写成公司项目或 NL2DSL 已上线能力。

### 必须补的能力与深度

| 优先级 | 主题 | 必须掌握 | 面试验收问题 |
| --- | --- | --- | --- |
| P0 | 工具设计与 MCP | 工具参数/返回 Schema、错误分类、超时、重试与幂等；区分直接集成的函数工具和 MCP 服务提供的工具；授权由服务端执行 | “模型填了未经授权的工单 ID，哪一层拦？” |
| P0 | 上下文与记忆 | 区分当前任务状态、会话历史、长期记忆和 RAG 资料；会裁剪、摘要、检索历史，并处理过期与敏感信息 | “聊了 100 轮，既不超上下文又不忘关键约束，怎么做？” |
| P0 | 持久化、恢复与人工审批 | 保存执行状态；暂停后用稳定任务 ID 恢复；审批前后验证身份与参数；副作用工具有幂等键 | “审批时进程重启了，恢复后会不会重复关闭工单？” |
| P0 | 执行安全与测试 | 工具最小权限、读写分离、外部内容不可信；模拟工具调用、越权、注入、循环和失败恢复 | “知识库文档写着‘忽略审批’，Agent 会不会照做？” |
| P1 | Agent Trace、评测与成本 | 记录模型调用、工具调用、审批和失败分支；固定数据集看任务完成率、工具选择正确率、越权率、耗时与成本 | “最终答对了但调用了错误工具，算成功吗？” |
| P2 | 多 Agent 编排与模型路由 | 比较单 Agent+工具、主 Agent 调专家、handoff；设置步数/Token/耗时预算，按任务复杂度路由 | “为什么不直接上三个 Agent？何时升级模型？” |

**边界提醒：** 不要求掌握 MCP 规范的全部细节，也不要求同时学习多个 Agent SDK。选一个框架做通用练习即可；先把工具、安全、恢复和测试做对，再考虑多 Agent。MCP 的协议细节以[官方工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)和[授权规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)为准。

### 每周详细作业

| 周 | 学习与实现 | 必须交付的证据 |
| --- | --- | --- |
| 13：工具与 MCP | 先写 3 个只读工具和 1 个有副作用的关闭工具；定义输入/输出 Schema、错误与超时。让至少 1 个只读工具通过 MCP 接入，其他工具可保留本地函数形式；服务端验证用户与工单归属 | 工具契约表、成功/非法参数/越权/超时各 1 个测试；口述 MCP 与普通函数调用的区别 |
| 14：上下文与记忆 | 加会话 ID 和持久化历史；区分会话状态与知识库资料；设计历史裁剪或摘要，注明摘要可能丢失哪些关键约束；模拟跨会话过期信息 | 连续多轮提问仍保留当前工单 ID 和审批状态；敏感信息不写入共享长期记忆；有 1 个长对话失败案例及修正记录 |
| 15：暂停、审批与恢复 | 关闭工单前暂停并等待人工批准；重启进程后使用同一任务 ID 恢复；重新校验审批人、工单 ID、动作和过期时间；关闭操作使用幂等键 | 批准/拒绝/超时/重启恢复/重复提交 5 类自动化测试；能解释状态存储与业务数据库各负责什么。参考[LangGraph 持久化](https://docs.langchain.com/oss/python/langgraph/persistence)和[中断](https://docs.langchain.com/oss/python/langgraph/interrupts) |
| 16：评测与面试 | 固定至少 20 条样例：正常查询、缺信息、错误工具、越权、注入式知识文档、模型超时、审批拒绝等；保留每条 Trace，统计成功/失败和成本；最后比较单 Agent 与多 Agent 方案 | 一份可复现评测表，写明分母、模型/版本、环境、失败样本；5 分钟演示并经得起“为什么不用多 Agent”的追问。可参考[Agent 测试](https://openai.github.io/openai-agents-python/testing/)与[编排模式](https://openai.github.io/openai-agents-python/multi_agent/) |

### 补充计划通关标准

1. **能独立运行：** 陌生人按 README 启动后，可以完成查询和生成建议；关闭工单未经授权或批准时一定失败。
2. **能复现故障：** 至少演示一次工具超时、一次进程重启恢复、一次知识库提示词注入；指出 Trace 中的失败位置和处理结果。
3. **能解释取舍：** 不看稿说明为什么当前先用单 Agent、哪些情况需要 handoff、多 Agent 带来什么上下文/权限/成本问题。
4. **能诚实展示：** 简历或面试标注为“个人练习/独立作品”；只有确实亲自实现、测试和理解的部分才写成个人贡献。
