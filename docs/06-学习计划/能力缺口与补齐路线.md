# 能力缺口与补齐路线（总控表）

> **这份文档怎么用**：它是整套面试材料的总控清单。每季度翻一次，按 checkbox 打勾。
>
> **打勾的标准不是"看完了"，而是三选一**：
> - 能**演示**（有跑得起来的产物）
> - 能**回答**（面试官追问三层不卡）
> - 有**产出**（简历上能写一行、或能拿出数据）
>
> 只做"读过文档"不算完成——那只能叫"知道"，不叫"会"。

---

## 一、先定位：你现在是什么样的人

> **一个工程严谨度很高、但 Agent 形态单一的后端架构师。**

| 你的优势（护城河） | 你的短板（结构性） |
|---|---|
| 评测体系设计（canonical + 二元判定 + 基线门禁） | **只会"单次 + 固定图"**，没写过自主循环 |
| 安全护栏（10 层防御 + 自己审出 7 个真实漏洞） | **工具调用零落地**（无 `bind_tools`/`ToolNode`/MCP） |
| 后端可靠性（8 年，50+ 台机器、日千万级） | **只有一种框架**（LangGraph + 自研，没对比过 Dify/Coze/AutoGen） |
| 数据/语义层（指标口径治理，比多数 ChatBI 候选人深） | 多轮/记忆只有设计，没有实现 |
| 领域闭环（DSL 契约、权限注入、审计） | 模型层只有"会用 API"的水平 |

**结论：你的问题不是知识点不够，是 Agent 形态太单一。**
知识可以靠文档补，**形态只能靠写代码补**——所以下面 P0/P1 全是"动手"，不是"阅读"。

## 四、P0 详细

### ① 工具调用 + 自主循环（2–3 周）

**为什么第一**
面试官问"你们 Agent 支持工具调用吗"，第一次可以答"没有，我们是编排型"。第二次就会被归类为"用 LangGraph 做查询的后端"，而不是 Agent 开发。

**要做出什么**

- [ ] 工具注册表（name / description / JSON Schema）
- [ ] 3 个工具：查指标口径、查维度、提交查询
- [ ] ReAct 循环：模型决策 → 执行 → 结果回填 → 再决策
- [ ] 循环条件：有 `tool_calls` 继续，否则结束
- [ ] 最大步数限制（防死循环）
- [ ] 参数校验：`enum` 收敛 + 服务端二次校验
- [ ] 错误信息写给模型看（"指标不存在，可用：…"）

**验收标准**
> 能现场演示：问一句"GMV 怎么算的、顺便查上个月华东的 GMV"，Agent 自动分两步调用工具并给出答案。

**参考**：[工具调用与 MCP 设计题](../04-设计题/工具调用与MCP设计题.md)

---

### ② 失败恢复与循环终止（1 周）

**为什么紧跟第一**
这是"demo 级"和"生产级"的分界线，也是你 8 年后端唯一能压过算法背景候选人的地方。

**要做出什么**

- [ ] 超时：每个工具独立超时，返回可读错误而不是抛异常
- [ ] 重试：只对幂等工具，带指数退避，有次数上限
- [ ] 熔断：同一工具连续失败 N 次，本轮禁用
- [ ] 终止：循环超过 N 步强制收敛并降级
- [ ] 人工接管：高风险动作挂起等审批（可复用 `human_review`）
- [ ] 每次调用写审计（谁、何时、调了什么、参数、耗时）

**验收标准**
> 能讲清："工具 A 超时 3 次之后我怎么处理"——不是"重试一下"，而是完整的分级策略。

## 五、P1 详细

### ③ 多轮与记忆（1–2 周）

**为什么第三**：知识层已写完设计题，差的只是实现。低于工具调用，因为很多 Agent 场景并不需要多轮。

- [ ] `session_id` 与 `query_id` 拆分
- [ ] 检查点持久化（InMemory → Sqlite/Postgres）
- [ ] 指代改写节点（规则优先 + LLM 兜底 + 失败降级）
- [ ] 澄清闭环（`item_id` + `clarification_answers` 回灌）
- [ ] 滚动摘要（最近 3 轮原文 + 更早摘要）

**验收标准**：3 轮对话能正确处理"那华南呢""换成近30天"。

**参考**：[多轮记忆与澄清闭环设计题](../04-设计题/多轮记忆与澄清闭环设计题.md)

---

### ④ 成本与延迟工程（1 周）

**为什么重要**：现在只有定性描述（"省掉 100–300ms"），没有数字。高级岗一定会问"一次查询多少钱、P95 多少"。

- [ ] 单次查询 token 数 → 单次成本
- [ ] 端到端 P50 / P95 延迟
- [ ] 各节点耗时占比（哪段最贵）
- [ ] 优化手段：模型分级、语义缓存、预算熔断

**验收标准**：能报三个真实数字，且能说出"最贵的是哪一步、为什么、怎么降"。

---

### ⑤ 可观测性聚合（1 周）

**你的底子好**（节点级 trace + 审计表），缺的是聚合与标准。

- [ ] 失败类型聚合（召回不足 / 指标错 / 权限拒 / SQL 错 / 超时）
- [ ] trace 里补成本、延迟字段
- [ ] 接标准协议（OpenTelemetry GenAI 语义约定 或 Langfuse）
- [ ] 一张看板：成功率、澄清率、P95、日均成本

**验收标准**：能回答"这周失败最多的是哪一类，占多少"。

## 六、P2 详细

### ⑥ MCP server（1 周）

**成本低收益高**：把已有的元数据能力包成 MCP server，一周跑通，简历立刻可用，还能被 Cursor 演示。

- [ ] `explain_metric` / `list_dimensions` / `sample_values` 三个工具
- [ ] stdio 传输跑通
- [ ] 能被 Cursor 或 Claude Desktop 实际调用
- [ ] 加审计与超时

**验收标准**：在 IDE 里能直接让模型调用你的服务查指标。

---

### ⑦ 多 Agent（2 周）

**不能更早**：没有单 Agent 闭环时做多 Agent，只会做出"分不清职责的并行调用"。

- [ ] supervisor 模式：一个规划 Agent 决定调哪个子 Agent
- [ ] 2 个 worker（查询 / 解释）
- [ ] 结果聚合与冲突处理
- [ ] 能回答"什么时候**不该**用多 Agent"

**验收标准**：能对比"单 Agent + 工具"与"多 Agent"在同一任务上的准确率/成本。

---

### ⑧ 评测方法论补完（3–5 天）

**你的强项，补的是"可信度证明"**。

- [ ] Cohen's kappa 计算 + 人工金标集（30–50 条）
- [ ] bootstrap 置信区间
- [ ] 配对显著性检验
- [ ] 报告里写 `69.7% (95% CI: ...)` 而不是裸点估计

**验收标准**：能回答"你怎么证明这次提升不是噪声"，并给出区间。

**参考**：[评估方法论升级设计题](../04-设计题/评估方法论升级设计题.md)

## 八、明确不做

| 不碰 | 理由 |
|---|---|
| 微调（SFT/LoRA） | 应用层 Agent 岗基本不做，能判断"该不该微调"就够 |
| 多模态 | 除非目标岗明确要视觉/语音 |
| 知识图谱 | Agentic RAG 概念够用，不必真建图谱 |
| computer use / 浏览器自动化 | 另一套技能栈，投入产出比低 |
| 分布式训练 | 与岗位无关 |

## 十、怎么判断"补完了"（验收三问）

每项完成后，用这三个问题自测——**有一个答不上来就是没完成**：

```
① 能演示吗？        打开就能跑，不是"理论上可以"
② 能被追问三层吗？  第 1 层原理、第 2 层你的选择、第 3 层边界/失败
③ 有产出吗？        简历一行 / 一个数字 / 一份文档
```

举例，以"工具调用"为例：

```
① 演示：问一句话，Agent 自动调两个工具并给答案
② 追问：
   一问"schema 怎么设计" → 动词命名 + enum + description 写何时用
   二问"参数错了怎么办" → 校验 + 错误回灌重试 + 降级
   三问"工具越权怎么办" → 工具级 RBAC + 参数白名单 + 审计
③ 产出：简历加一行"实现工具调用闭环，含 3 个元数据工具与失败恢复"
```

## 十一、面试口径速查

| 被问 | 一句话 |
|---|---|
| 你们 Agent 支持工具调用吗 | "目前是编排型；元数据类工具我设计了方案（注册表 + ToolNode + 审计），还没落地" |
| 什么时候该用多 Agent | "多数场景单 Agent + 工具就够；多 Agent 只在需要不同权限边界或独立上下文时才有价值" |
| 自主循环怎么防死循环 | "最大步数 + 同工具连续失败熔断 + 超时降级 + 高风险动作挂起人审" |
| 一次查询多少钱 | "报出 token 数 × 单价 + P95 延迟 + 最贵的那一步"（补完 ④ 之后） |
| 你怎么证明提升不是噪声 | "配对 bootstrap，差值 CI 不含 0 才算显著"（补完 ⑧ 之后） |
| 你的 Agent 和别人的区别 | "我把不可信的东西关进结构化契约里——DSL 白名单 + 参数化构建 + 审计；这不是演示级 Agent 会做的事" |
