# nl2dsl-interview-kit

AI Agent / NL2DSL 方向的面试资料库。

**核心约定：`03-专项` 只放"项目里真的做了的"，`04-设计题` 只放"没做但我知道该怎么做的"。两者物理隔离，面试时不会把设计说成事实。**

> 对应源码工程：`D:\demo\db-gpt\NL2DSL`（简历中提到的开源实现 `kobegy248/nl2dsl-engine`）。
> 本仓库只放资料，不放代码；文中提到的源码路径请到上面的工程目录里打开。

## 目录结构

```
docs/
├── 00-项目资料/   NL2DSL 项目流程图（HTML）
├── 01-简历/       简历正文（对外的唯一版本）
├── 02-项目题库/   项目知识点、高频题、优先级分级
├── 03-专项/       ✅ 已实现能力深挖（有代码证据，可以说"我做过"）
├── 04-设计题/     ❌ 未实现能力的设计方案（只能说"我知道怎么做"）
├── 05-模拟面试/   模拟训练、追问清单、参考答案、速查卡
├── 06-学习计划/   后端转 AI 应用的路线图
├── 07-后端与架构/ Java 微服务 + 技术负责人叙事（对标偏架构/负责人的 JD）
└── 99-归档/       历史计划与旧稿（不作为当前材料使用）
```

## 两个文件夹怎么用

| | `03-专项` | `04-设计题` |
|---|---|---|
| 内容 | 项目里**已经实现**的做法 | 项目里**没有**的技术与方案 |
| 面试口径 | "我做过，代码在 X 文件的第 N 行" | "我们没做，如果要做我会这样设计" |
| 风险 | 低——每句都有证据 | **高——绝对不能说成"我们做了"** |
| 什么时候看 | 面试前必看 | 被追问"那你们怎么处理 X"时再看 |

> 判断方法：打开文件先看顶部有没有 **「证据边界」** 声明块。有 = 设计题，里面全部是提案。

## 建议使用顺序

0. **先看总控表** → [能力缺口与补齐路线（总控表）](<docs/06-学习计划/能力缺口与补齐路线.md>)：P0–P3 优先级 + 90 天排期 + 可勾选清单，用来查漏补缺
1. **先定简历口径** → `01-简历`
2. **把项目讲到能自圆其说** → `02-项目题库`
3. **吃透已实现能力** → `03-专项`（五份，全部有代码证据）
4. **备好设计弹药** → `04-设计题`（六份，只在被追问时用）
5. **练表达** → `05-模拟面试`（录音 → 对照追问清单 → 回看参考答案）
6. **最后过一遍速查卡** → [面试总结速查](<docs/05-模拟面试/高宇-NL2DSL面试总结速查.md>)
